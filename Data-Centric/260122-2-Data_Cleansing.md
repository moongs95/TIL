# 데이터 클렌징 및 IAA 평가

## 1. 데이터 클렌징 개요

### 라벨링 에러의 종류

데이터 클렌징을 이해하기 위해서는 먼저 라벨링 에러의 종류를 파악해야 함

#### 1. 휴먼 에러(Human Error)
작업자들의 실수, 경험 부족, 이해력 부족 등 **사람이기에 발생할 수 있는 에러**

#### 2. 라벨링 규칙 에러(Labeling Rule Error)
**라벨링 규칙이 잘못된 경우에 발생할 수 있는 에러**

발생 원인:
- 라벨링 가이드라인이나 교육에서 잘못 설명한 경우
- 라벨링 규칙이 중의적이라 작업자마다 서로 다르게 해석될 수 있는 경우
- 라벨링 도중에 규칙이 변경된 경우
- 라벨링 규칙이 다양한 예외들을 처리하지 못하는 경우
- 라벨링 규칙과 관련된 질의 응답에서 일관성이 없는 경우

### 데이터 클렌징(Data Cleansing) 정의

라벨링 에러들을 수정하여 데이터의 품질을 향상시키는 것

#### 클렌징 방법 분류
1. **직접 클렌징**: 예외가 많아 직접 다시 라벨링해야 하는 경우
2. **규칙 기반 클렌징**: 코드를 통해 손쉽게 수정할 수 있는 경우

### 데이터 클렌징의 필요성

#### 모델 성능 향상
- 라벨링 에러는 노이즈이기 때문에 모델이 의도한 대로 동작하지 않거나 성능이 저하될 수 있음
- 라벨링 에러가 존재하는 데이터를 제외하거나 클렌징함으로써 모델 성능 향상 가능

#### 지속적인 품질 개선
- 반복적으로 발생하는 라벨링 에러는 교육 또는 가이드라인에 업데이트하여 후속 작업에 반영

## 2. 데이터 클렌징 방법

### 라벨링 에러 확인 방법

데이터 클렌징을 하기에 앞서, 데이터에 어떤 라벨링 에러가 있는지 확인 필요

#### 4가지 주요 확인 방법
```
1. 샘플링 후 직접 검수
2. 모델 결과 분석
3. IAA 분석
4. Confident Learning 활용
```

### 1) 샘플링 후 직접 검수

가장 손쉽게 할 수 있는 방법으로 라벨링 결과를 사람이 직접 검수

#### 검수 방법 종류

**관리자 직접 검토**
- ✅ 가장 신뢰도가 높은 방법
- ❌ 데이터 규모가 커질수록 실행 어려움

**제3의 작업자가 검토**
- ✅ 라벨링 작업에 참여하지 않은 작업자들이 검수하여 객관성 향상
- ❌ 제3의 작업자에 대한 추가 비용 발생

**작업에 참여한 작업자 간 교차 검증**
- ✅ 숙련된 작업자들끼리 교차 검증하기 때문에 가장 밸런스가 좋은 방법

> 💡 데이터 수량이 적은 경우 전부 검수하는 것이 가장 좋으나, 그렇지 않은 경우 샘플링 후 검수 진행

### 2) 모델 결과 분석

모델의 정량평가와 정성평가를 통해 라벨링 에러를 발견하는 방법

#### 분석 프로세스
```
정량평가/정성평가로 성능이 낮은 부분 발견
    ↓
해당 부분을 중심으로 직접 검수 진행
    ↓
성능 저하 원인 분석
- 난이도가 높은 것인지
- 모델의 문제인지
- 라벨링 에러로 인한 것인지
    ↓
라벨링 에러가 원인인 경우
    ↓
해당 부분 중심으로 데이터 클렌징 진행
```

> ⚠️ **모델 지식이 필수적!** 모델에 fit한 데이터 구축 필요

### 3) IAA 분석

**IAA(Inter-Annotator Agreement)**: 동일한 작업에 할당된 작업자들 간의 일치 정도

#### IAA 활용 방법
- 데이터의 일치도를 정량적으로 확인
- 일치도가 낮은 작업자를 찾아내거나, 일치도가 낮은 라벨을 찾아낼 수 있음
- 일치도가 낮은 작업자가 작업한 데이터만 클렌징하거나, 일치도가 낮은 라벨만 클렌징 가능

### 4) Confident Learning 활용

에러가 있는 라벨과 정답 라벨 간의 결합 분포와 라벨별 임계값을 활용하여 라벨링 에러를 식별하고 처리하는 방법

#### 동작 원리
- 데이터의 예측 확률이 라벨별 임계값을 넘지 못하는 경우
- 해당 데이터에는 라벨링 에러가 존재하는 것으로 판단
- 데이터에서 제외 후 학습에 사용

## 3. 데이터 클렌징 실행

### 직접 클렌징 (다시 라벨링)

라벨링 에러가 규칙적이지 않아 사람이 하나씩 직접 클렌징(다시 라벨링)하는 방법

#### 장점
- ✅ 휴먼 에러나 예외 케이스에 유연하게 대응 가능
- ✅ 테스트 세트(Ground Truth)와 같이 정답을 만드는 경우 데이터 정확도 향상

#### 단점
- ❌ 사람을 통해 직접 클렌징하므로 비용 문제 발생 가능
- ❌ 여전히 휴먼 에러에 취약하며, 클렌징 후에도 휴먼 에러 발생 가능
- ❌ 완벽한 데이터를 만들기 위해서는 **여러 번의 이터레이션 필요**

### 규칙 기반으로 코드를 통한 클렌징

라벨링 에러가 규칙적인 경우에 코드를 통해서 클렌징하는 방법

#### 장점
- ✅ 라벨링 에러에 대한 규칙만 정확하게 파악되면 쉽고 빠르게 클렌징 진행
- ✅ 일괄적으로 라벨링 에러를 클렌징하므로 라벨링의 일관성과 정확도 향상
- ✅ 사람이 직접 클렌징하지 않으므로 시간과 비용 절약

#### 단점
- ❌ 라벨링 에러가 규칙적인 경우는 많지 않음
- ❌ 라벨링 에러를 분석하고 규칙을 만들고 코딩하는데 더 많은 시간 소요 가능
- ❌ 데이터 수량이 적은 경우에는 직접 클렌징하는 방법이 더 효과적일 수 있음

### 라벨링 규칙 수정

라벨링 에러를 확인하거나 데이터를 클렌징하는 중에 라벨링 규칙의 수정이 필요한 경우 규칙 업데이트

#### 추가 반영 사항
- 라벨링 과정 중에 발견되는 예외
- 자주 묻는 질문(FAQ)

#### 주의사항

**⚠️ 라벨링 과정 중에 라벨링 규칙을 수정하지 않음**
- 작업자들에게 혼란 야기 가능
- 라벨링 규칙이 수정되는 시점을 기준으로 서로 다른 데이터가 됨을 인지
- 그럼에도 수정이 필요하다면, 수정하기 전의 데이터를 어떻게 수정할 것인지 미리 계획

**📝 가이드라인 또는 교육에 수정된 부분 반영 시**
- 어떤 부분이 수정되었는지 명시하여 작업자들의 이해도 향상

## 4. IAA (Inter-Annotator Agreement)

### IAA 정의

동일한 작업에 할당된 작업자들 간의 일치 정도를 의미
- 범주형 또는 명목형 데이터에 주로 활용

### IAA의 필요성

#### 1. 정량적으로 데이터 품질 평가

**IAA가 높다는 것 = 라벨링이 일관성 있게 되었다는 것**
- 데이터에 노이즈가 적다는 의미
- 모델 성능에 긍정적인 영향

**모델 없이도 데이터를 정량적으로 평가 가능**
- 휴리스틱한 데이터 품질 평가 방법은 많지만, 정량적인 방법은 많지 않음
- 일반적으로 모델의 성능을 바탕으로 데이터의 품질을 평가
- IAA를 사용하면 자체적으로 데이터의 품질을 정량적으로 평가 가능

#### 2. IAA 분석을 통한 데이터 품질 개선

IAA에 영향을 주는 요인:
- 작업의 난이도
- 데이터의 퀄리티
- 작업자의 실력
- 작업자들의 조합
- 라벨링 규칙
- 라벨링 가이드라인과 교육

→ IAA가 낮다면, IAA를 분석하여 원인을 찾아 데이터의 품질 개선 가능

### IAA의 한계

#### IAA ≠ 정확성

> ⚠️ **중요**: IAA는 일치도를 평가하기 때문에, IAA가 높다고 하여 라벨링이 정확하다는 것은 아님

예시:
- 모든 작업자가 틀리게 라벨링을 했더라도, 모두 일치했다면 IAA는 높아짐
- IAA는 데이터의 모든 방면에 대해서 품질을 평가하는 것이 아니라, **일치도만을 평가**하는 방법

## 5. IAA 평가 방법

### Cohen's Kappa (κ)

범주형 변수를 평가하거나 분류할 때, **두 작업자 간의 일치 정도**를 측정하는 메트릭

### Fleiss Kappa

범주형 변수를 평가하거나 분류할 때, **세 명 이상의 작업자 간의 일치도**를 측정하는 메트릭

### F1-score

이진 분류의 통계적 분석에서 테스트 정확도의 측정값
- 테스트의 정밀도(Precision)와 재현율(Recall)로 계산

#### F1-score in IAA

**활용 방법**
- 한 작업자의 라벨링 결과를 실제값으로 가정
- 다른 한 작업자의 라벨링 결과를 예측값으로 가정
- F1-score를 계산하여 작업자들 간의 일치도를 계산

**장점: 다양한 결과 추출 가능**
- 두 작업자 간의 일치 정도 (Cohen's Kappa와 유사)
- 세 명 이상의 작업자 간의 일치도 (Fleiss Kappa와 유사)
- **라벨별 작업자 간의 일치도**

## 6. IAA를 활용한 데이터 클렌징

### IAA만을 활용한 데이터 클렌징

#### 개요

IAA는 동일한 작업에 할당된 작업자들 간의 일치 정도를 의미하며, 다음과 같은 부분에 영향을 받음:
- 작업의 난이도
- 데이터의 퀄리티
- 작업자의 실력
- 작업자들의 조합
- 라벨링 규칙
- 라벨링 가이드라인과 교육

→ **IAA가 낮은 원인을 분석하여 데이터 클렌징에 활용 가능!**

### IAA 활용 예시

#### 예시 1: 세 작업자의 IAA가 모두 높은 경우

**상황**: 데이터의 IAA가 높은 경우

**분석**
- 세 작업자의 IAA가 모두 높다 = 데이터의 일치도가 매우 높음
- 세 작업자가 모두 동일하게 잘못된 라벨링을 했는지만 주의
- 보통 라벨링 규칙, 가이드라인, 교육에 의해 라벨링 에러 발생 가능

**클렌징 방법**
- 라벨링 에러가 있더라도 일관성 있기 때문에 **규칙 기반으로 코드를 통한 클렌징** 가능
- ✅ 가장 이상적인 경우

#### 예시 2: 세 작업자 중 한 작업자의 IAA가 낮은 경우

**상황**
- A 작업자와 B 작업자 간의 IAA는 높음
- C 작업자와 A, B 작업자 간의 IAA는 낮음

**분석**
- C 작업자의 실력 부족으로 IAA가 낮은 것이라고 추측 가능

**클렌징 방법**
1. C 작업자만 재교육
2. C 작업자의 데이터만 클렌징
3. C 작업자의 데이터만 제거

#### 예시 3: 세 작업자의 IAA가 모두 낮은 경우

**상황**: 데이터의 IAA가 낮은 경우

**분석**
- 세 작업자 간의 IAA가 매우 낮아 데이터 전체적으로 일치도가 낮은 상태

**예상 원인**
- 작업의 난이도
- 데이터의 퀄리티
- 작업자의 실력
- 라벨링 규칙
- 라벨링 가이드라인과 교육

**클렌징 방법**
- IAA만으로는 원인 특정이 어려움
- 위 원인들에 대해서 하나씩 검토 필요 → **소거법 사용**

#### 예시 4: 특정한 라벨의 IAA가 낮은 경우

**활용 방법**
- IAA 평가 방법 중 하나인 **F1-score**를 통해 작업자 간의 라벨별 IAA 계산 가능
- 어떤 작업자가 어떤 라벨에서 일치도가 낮은지 확인 가능
- 예시 2, 3에 해당 방법을 적용하면 더욱 정확하게 원인 특정 가능

**데이터 전체의 라벨별 IAA 확인**
- 본인과의 IAA(F1-score)를 제외하고 작업자 간의 라벨별 IAA를 평균

#### 예시 5: 작업자들을 선발하는 경우

**상황**: 5명의 작업자 중 3명을 선발

**활용 방법**
- IAA를 작업자 평가 지표 중 하나로 사용하여 작업자 선발에 활용
- 작업자 간의 IAA를 비교하여 일치도가 낮은 작업자 제외
- 일치도가 높은 작업자들을 선발하면 높은 IAA의 데이터 구축 가능

> ⚠️ **주의**: IAA는 정확도가 아닌 일치도라는 점을 인지하고 평가

### IAA만을 활용한 데이터 클렌징의 한계

#### 한계점

**1. 정확도 파악 어려움**
- IAA만으로는 모델의 결과를 모르더라도 데이터 클렌징을 할 수 있다는 장점
- 근본적으로 IAA는 일치도만 평가하므로 라벨링의 정확도는 파악 어려움
- IAA가 매우 높더라도 라벨링 에러가 존재할 수 있다는 가능성 배제 불가

**2. 원인 특정의 어려움**
- IAA에 영향을 줄 수 있는 원인들이 다양하여 라벨링 에러의 원인을 추측할 수밖에 없음
- 원인이 다양한 경우에는 특정하기가 쉽지 않고 전체적인 검토 필요

> 💡 **해결 방법**: 다른 Metric과 함께 사용하여 어느 정도 보완 가능!

## 7. IAA와 다른 Metric을 활용한 데이터 클렌징

### 모델 F1-score 활용

**모델 F1-score**: 테스트 세트를 바탕으로 정답과 모델의 추론 결과를 비교하여 평가한 것

#### 인과관계 활용

**기본 원리**
- 일반적으로 IAA가 높을수록 데이터의 노이즈가 적음
- 따라서 모델의 높은 성능을 기대할 수 있음
- 도메인에 따라 다르지만, IAA의 F1-score와 모델의 F1-score 간에 어느 정도 인과관계 존재

**활용 방법**
- 이러한 인과관계를 활용하여 성능 저하의 원인이 데이터에 있는지 모델에 있는지 어느 정도 추측 가능

> ⚠️ **주의**: 모델의 학습이 완료되어 결과가 나온 다음에 사용할 수 있기에 **모델 의존적인 방법**

#### 분석 예시

8개의 라벨을 분류하는 데이터의 IAA F1-Score와 모델 F1-score를 가정

**패턴 분석**
- IAA F1-score가 높으면 → 모델 F1-score도 높음
- IAA F1-score가 낮으면 → 모델 F1-score가 낮음

**의사결정 활용**

| 상황 | IAA | 모델 성능 | 개선 방향 |
|-----|-----|---------|----------|
| 케이스 1 | 높음 | 낮음 | 모델 개선 |
| 케이스 2 | 낮음 | 낮음 | 데이터 개선 |

→ 데이터를 개선할지 모델을 개선할지 **의사결정을 위한 참고 자료**로 사용 가능

#### 예외 케이스

당연하게도 절대적인 것은 아니며 언제나 예외는 존재:
- IAA는 매우 낮지만 모델의 성능이 매우 높은 경우
- IAA는 비슷한데 모델의 성능이 상반되는 경우

→ 이러한 **예외 케이스들을 상세하게 분석**하면 성능 개선의 실마리를 찾을 수 있음

### 작업자 F1-score 활용

**작업자 F1-score**: 테스트 세트를 바탕으로 정답과 작업자의 라벨링 결과를 비교하여 평가한 것

#### 장점
- ✅ IAA의 약점 중 하나인 **라벨링의 정확도를 평가** 가능
- ✅ 모델 학습 여부와는 별개로 사용 가능 → **모델 독립적인 방법**

#### 단점
- ❌ 작업자들을 평가하기 위한 **테스트 세트가 별도로 준비**되어야 함
- ❌ 라벨링 평가를 위한 라벨링을 해야 하는 **모순적인 상황** 발생 가능
- ❌ 사람이 라벨링하는 이상 테스트 세트의 라벨링을 정확하게 만드는 것도 쉽지 않음
- ❌ **추가 비용 발생**

### 데이터 클렌징 프로세스
```
라벨링 에러 확인
    ↓
┌─────────────────────────────┐
│ 1. 샘플링 후 직접 검수      │
│ 2. 모델 결과 분석           │
│ 3. IAA 분석                 │
│ 4. Confident Learning 활용  │
└─────────────────────────────┘
    ↓
클렌징 방법 선택
    ↓
┌────────────────┬────────────────┐
│ 직접 클렌징    │ 규칙 기반      │
│ (예외 많음)    │ (규칙적)       │
└────────────────┴────────────────┘
    ↓
라벨링 규칙 수정 (필요시)
    ↓
품질 개선
```

### IAA 활용 전략

| 상황 | IAA 상태 | 원인 추정 | 대응 방안 |
|-----|---------|----------|----------|
| 예시 1 | 모두 높음 | 일관성 있는 라벨링 | 규칙 기반 클렌징 |
| 예시 2 | 한 작업자만 낮음 | 특정 작업자 실력 부족 | 해당 작업자만 재교육/클렌징 |
| 예시 3 | 모두 낮음 | 다양한 원인 가능 | 소거법으로 원인 검토 |
| 예시 4 | 특정 라벨만 낮음 | 특정 라벨 규칙 문제 | F1-score로 라벨별 분석 |
| 예시 5 | 작업자별 차이 | 작업자 역량 차이 | IAA 기반 작업자 선발 |

### 클렌징 방법 선택 가이드

**직접 클렌징이 적합한 경우**
- 라벨링 에러가 불규칙적인 경우
- 예외 케이스가 많은 경우
- 데이터 수량이 적은 경우
- 높은 정확도가 필요한 경우 (테스트 세트)

**규칙 기반 클렌징이 적합한 경우**
- 라벨링 에러가 규칙적인 경우
- 일관성 있는 에러 패턴이 있는 경우
- 데이터 수량이 많은 경우
- 비용과 시간을 절약해야 하는 경우

### 평가 메트릭 조합 전략
```
IAA만 활용
├─ 장점: 모델 독립적, 빠른 평가
└─ 단점: 정확도 파악 어려움

IAA + 모델 F1-score
├─ 장점: 데이터/모델 개선 방향 결정
└─ 단점: 모델 의존적

IAA + 작업자 F1-score
├─ 장점: 정확도 평가 가능, 모델 독립적
└─ 단점: 테스트 세트 필요, 추가 비용
```
