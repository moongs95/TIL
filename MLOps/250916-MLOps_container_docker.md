# Container

- 어떤 것을 실행하기 위해 필요한 모든 요소를 포함하는 소프트웨어 패키지
- 운영체제를 가상화한 형식이기 때문에, 클라우드에서부터 개인 노트북에 이르기까지 어디서나 실행 가능
- SW 개발팀은 컨테이너화를 통해 더욱 신속하게 작업을 진행하고 효율적으로 소프트웨어 배포할 수 있음 -> 확장성

- 정의 : Container는 애플리케이션과 그 필요한 모든 것(코드, 런타임, 시스템 도구, 시스템 라이브러리 등)을 포함하는 표준화된 단위, 애플리케이션은 어떤 컴퓨팅 환경에서도 일관되게 실행될 수 있음
- 작동 원리 : Container는 운영 체제의 커널을 공유, 각 컨테이너는 서로 격리된 공간에서 실행, 가상환경과 유사
- 특징 : 독립된 실행 환경, 경량화, 이미지 기반

## 주요 구성요소

- Image : 애플리케이션과 그 실행에 필요한 모든 파일을 포함한 불변의 템플릿
- Registry : image가 저장되고 공유되는 곳(public, private)
- Container Runtime : Container를 실행하기 위한 환경을 제공

## 필요성

- 환경 일관성 제공
- 자원 효율성 증가
- 배포 및 확장 용이성

## 장단점

### 장점

- 경량성 및 빠른 시작
- 일관된 환경
- 효율적인 자원 사용
- 격리와 분리

### 단점

- 보안 취약성
- 관리 복잡성

## 실제 사례

- 멀티 클라우드 및 하이브리드 클라우드 환경에서 사용
- 대규모 머신러닝 파이프라인 최적화
- 지속적 통합 및 배포(CI/CD)를 위한 활용

## MLOps에서의 Container 인프라

- MLOps에서의 중요성 : 컨테이너는 MLOps의 핵심 구성 요소로 자리 잡음 -> 동일한 환경에서 작업, 모델의 개발, 테스트, 배포 과정 효율적으로 만듦
- 효율성과 확장성 : 컨테이너는 머신러닝 파이프라인의 효율성 증대, 클라우드 환경에서의 확장성 제공 -> MLOps의 유연성과 속도를 증가
- 앞으로의 전망 : 컨테이너 기술은 계속 발전, MLOps의 미래에 큰 영향, 멀티 클라우드 및 하이브리드 클라우드 환경에서의 활용도가 증가할 것으로 예상

# Docker

- 정의 : Docker는 컨테이너화 기술을 사용하여 애플리케이션을 패키징하고 배포하는 데 사용되는 오픈소스 플랫폼
- 특징 : 경량화된 컨테이너를 제공하며, 독립적, 이식성이 뛰어남, 환경에 구애 받지 않는 애플리케이션 실행

## 주요 구성요소

- Docker Image : 애플리케이션을 실행하는데 필요한 모든 파일과 설정을 포함하는 템플릿
- Docker Container : Image를 기반으로 실행되는 실행 Instance → 실체
- Docker Daemon : Docker Image와 Container를 관리하는 background service → 실행, 확인, 종료 작업 등
- Docker Registry : 외부 Image 저장소, 다른 사람들이 공유한 이미지를 사용할 수도 있고, private 하게도 저장 가능
- Docker Client : 사용자가 Docker Daemon과 상호작용하는 Interface
