# 📌 TIL: Data-Centric AI란?

## 01. Data-Centric AI란?

### 1.1 데이터의 중요성

AI 시스템은 다음 두 요소로 구성된다.

AI System = Code(모델, 알고리즘) + Data(학습/검증/테스트 데이터)


AI 시스템의 성능을 개선하는 방법은 크게 두 가지다.

- **모델(코드)을 개선**
- **데이터를 개선**

#### Why Data?

- 데이터는 모델을 학습시키는 **재료**
- 양질의 데이터 확보 및 클렌징 → **준비 단계 (80%)**
- 모델 학습 및 추론 → **행동 단계 (20%)**

> 요리 비유  
> - 재료 준비(데이터 수집·정제): 80%  
> - 요리(모델 학습): 20%

⚠️ 문제점  
- 동일한 데이터에 대해 서로 다른 어노테이션/라벨이 붙을 수 있음
- 이는 **노이즈**를 발생시키고 모델 품질 저하로 이어짐

👉 **AI 프로젝트에서 데이터가 차지하는 비중: 약 80%**

---

### 1.2 Data-Centric AI의 정의

#### Model-Centric AI

- 전통적이고 여전히 많이 쓰이는 방식
- **모델을 중심**으로 AI 시스템을 개선
- 데이터는 고정, 모델/알고리즘을 반복적으로 개선

**특징**
- 가능한 많은 데이터를 수집
- 데이터 노이즈를 견딜 수 있는 강한 모델 개발

#### Data-Centric AI

- 2020년대 이후 주목받기 시작
- **데이터를 중심**으로 AI 시스템을 개선
- 코드는 고정, 데이터를 반복적으로 개선

**특징**
- 데이터의 **일관성(consistency)** 확보
- 체계적인 데이터 품질 관리
- 다양한 도구를 활용한 데이터 정제 및 검증

📌 요약
- 코드를 개선 → **Model-Centric AI**
- 데이터를 개선 → **Data-Centric AI**

---

### 1.3 MLOps

**MLOps (Machine Learning Operations)**  
MLOps = ML + DevOps


- 머신러닝 모델을 **안정적·효율적으로 배포 및 운영**하기 위한 패러다임
- 데이터 수집, 버전 관리, 검증, 재학습을 포함한 **데이터 인프라 구축**이 핵심
- Data-Centric AI를 실현하기 위한 필수 요소

## 02. Data-Centric AI가 산업에 미친 영향

### 2.1 Pretraining & Fine-Tuning

#### 트랜스포머 기반 언어 모델

- Transformer 구조가 기존 LSTM 계열을 압도
- NLP 분야의 표준 모델 구조로 자리 잡음

#### 거대 언어 모델 (LLM)

- 파라미터 수가 많을수록 일반화 성능 향상
- 하지만:
  - 막대한 데이터
  - 막대한 연산 자원 필요
- 초거대 IT 기업만 직접 학습 가능

#### 해결책: Fine-Tuning

- 사전학습된 LLM을 **태스크에 맞게 재학습**
- 소량의 **고품질 데이터**만으로도 효과적인 성능 달성 가능

#### LoRA (Low-Rank Adaptation)

- 기존 파인튜닝 방식:
  - 모델 파라미터 일부/전체 재학습
  - 추가 레이어 학습
- **LoRA**
  - 사전학습 모델은 **완전히 고정(freeze)**
  - 낮은 랭크의 어텐션 행렬만 학습
  - 학습 비용과 데이터 요구량 감소

---

### 2.2 Prompt Engineering

#### 주요 개념

- **프롬프트(Prompt)**  
  - AI가 수행해야 할 작업을 설명하는 자연어 텍스트
  - 명확하고 간결할수록 좋음

- **프롬프트 엔지니어링(Prompt Engineering)**  
  - 생성 모델이 이해하기 쉽게 프롬프트를 구조화하는 과정
  - text-to-text, text-to-image 모델에 주로 사용

- **In-Context Learning**
  - 모델이 이전 컨텍스트를 활용해 새로운 작업을 수행
  - 예: 대화 맥락을 기억하고 응답

#### GPT-3를 통해 알게 된 사실

1️⃣ 입력에 **지시문을 포함**하면 태스크를 수행한다  
- 태스크를 텍스트로 명확히 제시 → 정답에 가까운 결과 출력
- 예제가 많을수록 성능 향상

2️⃣ **지시가 구체적일수록** 결과가 좋아진다  
- 프롬프트 설계가 성능에 직접적인 영향
- 일정 규모 이상의 LLM에서는 파인튜닝보다 효과적인 경우도 존재

## 03. Data-Centric AI 관련 연구

### 3.1 Data-Centric AI 주요 태스크

- **이상 탐지 및 제거 (Anomaly Detection & Removal)**
  - 분포에서 벗어난 비정상 데이터 탐지 및 제거

- **오류 감지 및 수정 (Error Detection & Correction)**
  - 데이터 오류를 시스템적으로 탐지
  - MLOps에서 매우 중요한 요소

- **데이터 증강 (Data Augmentation)**
  - 기존 데이터를 변형·확장하여 데이터 양 증가
  - 모델 일반화 성능 향상

- **피처 엔지니어링 (Feature Engineering)**
  - 기존 피처를 조합·변환하여 의미 있는 새로운 피처 생성

- **컨센서스 라벨링 (Consensus Labeling)**
  - 다수의 어노테이터 결과를 종합해 신뢰도 높은 라벨 생성

- **액티브 러닝 (Active Learning)**
  - 모델 학습 중 가장 중요한 샘플을 선택해 라벨 요청

- **커리큘럼 학습 (Curriculum Learning)**
  - 쉬운 데이터 → 어려운 데이터 순으로 학습 진행
