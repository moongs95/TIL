# 데이터 라벨링 가이드라인 및 규칙

## 1. 데이터 라벨링 개요

### 데이터 라벨링(Data Labeling) 정의

수집 및 전처리를 통해 획득한 원천 데이터를 구축 목적에 맞게 라벨/속성을 표기하는 작업

> 💡 가장 복잡하지만 확실한 **'직접 라벨링'** 방법을 중심으로 학습

---

## 2. 데이터 라벨링 프로세스

### 체계적인 라벨링 프로세스의 필요성

라벨링 시 고려해야 할 조건:

#### 구축 환경 및 조건 검토
원하는 조건을 만족시키기 위해 필요한 시간과 비용 재확인
- **작업자의 수준**: 필요한 전문성 정도
- **작업량 및 작업 난이도**: 인건비와 직결

#### 다양한 라벨링 툴 검토
검토한 조건 하에 가장 효율적인 방법 선정
- 무료 vs. 유료
- 아웃소싱 vs. 크라우드소싱

#### 라벨링에 대한 명확한 기준 마련
작업자에게 명료한 목표 및 방법 전달하여 품질 향상
- 어디까지 어떻게 라벨링할 것인가

### 라벨링 프로세스 6단계

```
라벨링 대상 설정(기획)
    ↓
가이드라인 작성(구체적인 edge case)
    ↓
라벨러 모집(기준 설정)
    ↓
라벨러 교육
    ↓
라벨링 진행 ←→ 반복
    ↓
라벨링 검수
    ↓
데이터 구축 완료
```

#### 용어 정리
- **라벨러(Labeler)**: '어노테이터(Annotator)' 또는 폭넓게 '작업자'라고도 함
- **라벨 vs. 어노테이션(Annotation; 주석)**
  - '라벨'은 협의의 의미를 가지므로 '어노테이션'을 사용하기도 함 (예: 문서 요약)

## 3. 라벨링 가이드라인 작성

### 가이드라인의 필수 구성 요소

#### 1. 데이터 개요
**목적**: 라벨링의 목적과 결과물 간단히 설명
- 예: OCR용 영수증 이미지 데이터

**작업 데이터**: 원천 데이터의 샘플을 직접 확인할 수 있는 형태로 첨부 후 설명
- 예: 글자 영역이 있는 영수증 실사 이미지

**작업 프로세스 요약**: 주요 작업 내용과 흐름 설명
- 예: 사전에 정의된 카테고리로 OCR로 인식할 텍스트를 분류 및 전사(받아쓰기)

#### 2. 용어 정의
커뮤니케이션을 위한 기본 용어 설명

**라벨링 관련 용어**
- 라벨링 기법, 데이터 및 라벨의 체계에 대한 설명
- 예: 텍스트박스, 온톨로지, 카테고리, 헤더, 엔티티

**라벨 해설**
- 분류나 태깅에 사용되는 라벨의 뜻과 적용 범위 설명
- 예: 공급자, 제품명, 수량, 금액, 총매출액

#### 3. 어노테이션 절차 (도구 사용법 포함)
사용할 라벨링 방법마다 어떤 순서로 툴을 사용하여 어노테이션을 진행하면 되는지 설명

#### 4. 어노테이션 규칙 및 Edge Case

**규칙**
- 어떤 개체를 어떻게 라벨링해야 하는지 상세하게 기술
- 같은 데이터가 다른 방식으로 라벨링되지 않도록 **통일성** 부여
- 예: 제품명이 여러 줄에 나눠 적혀 있을 경우 어떻게 라벨링할 것인지

**Edge Case**
- 라벨링이 애매모호한 경우나 기존 규칙에서 예외적인 경우
- **실제 사례를 캡처해서 설명**하여 라벨러의 이해를 높임
- 예: 영수증의 일부가 손상되었을 경우 어떻게 처리할 것인지

### 가이드라인 작성 시 주의사항

> ⚠️ 모든 요소는 **라벨러의 입장**에서 이해할 수 있는 용어와 흐름으로 서술

> ⚠️ 가이드라인이 변경되는 경우, 그 시점을 기준으로 전후의 데이터가 달라질 수 있음
> - 처음부터 완성도 있게 만들어 업데이트되지 않도록 하는 것이 좋음
> - 업데이트가 필요한 경우, 해당 내용을 참고하여 변경 전의 데이터를 클렌징해야 함

## 4. 컴퓨터 비전(CV) 라벨링

### CV 라벨링 기법 종류

#### 주요 기법
- **바운딩 박스(Bounding Box)**: 각 객체가 해당하는 위치를 직사각형 박스로 표기
- **OCR(Optical Character Recognition)**: 텍스트가 해당하는 위치를 직사각형 박스로 표기
- **큐보이드(Cuboid)**: 3D Bounding Box
- **폴리곤(Polygon)**: 바운딩 박스의 다각형 형태, 보다 상세한 객체 라벨링
- **폴리라인(Polyline)**: 선형 객체의 경계나 위치를 연속선으로 지정
- **의미 분할(Semantic Segmentation)**: 이미지의 각 픽셀을 라벨링
- **키포인트(Keypoint)**: 얼굴, 관절 등 객체의 주요 지점(특징)을 점으로 지정

### 바운딩 박스 규칙

#### 핵심 원칙
박스 내에 최대한 노이즈가 없게, 반대로 박스 밖에는 객체가 없게 하는 것
- 중의적인 표현 ❌
- 가능한 타이트하게
- 잘리지 않게
- **통일성, 일관성** 있게 라벨링

#### 규칙 예시

**예시 1**: 기호는 라벨링에서 제외하고, 띄어쓰기는 분리하여 박스를 그린다
- 띄어쓰기의 기준: 글자 너비의 ½ 이상
- 정량적 수치 제시로 객관성 확보
- 규칙이 없다면 라벨러마다 특수문자나 박스의 개수가 달라짐

**예시 2**: 특수 알파벳은 개별 박싱 후 기호로 처리한다
- ơ, ō, é, Å 전부 기호로 처리
- 라벨러 간 통일되지 않은 철자로 라벨링하지 않게끔 방지
- 첨자 사용 여부는 모델 목적에 따라 일관성 있게 결정

**예시 3**: 번진 글자, 거울에 비친 글자, 일부 삭제된 글자는 제외한다
- 규칙이 없을 경우 라벨러마다 라벨링한 객체의 개수와 텍스트의 범주가 달라짐
- 노이즈가 많이 포함된 객체를 라벨에 포함시켜 학습의 품질을 낮출 수 있음
- 주관적 판단 배제

**예시 4**: 명확히 보이는 가장 먼 객체를 기준으로 모든 객체를 라벨링한다
- 하나의 이미지에서 많은 객체를 라벨링해야 하는 경우, 어느 정도 크기까지 라벨링해야 하는지에 대한 기준 필요

**예시 5**: 다른 객체에 겹쳐 있는 경우, 온전한 모양을 추정하여 그린다
- 라벨링한 객체의 크기 및 범위가 라벨러마다 달라지지 않도록 규칙 마련
- 사람마다 '노이즈'라고 판단하는 기준이 다르므로 이를 통일

### 폴리라인 및 폴리곤 규칙

#### 사용 시 주의사항
- 바운딩 박스로 만들어진 라벨로 객체를 검출하는 경우가 대부분
- 폴리 계열은 라벨링에 비교적 많은 시간이 소요
- 특별한 경우를 라벨러에게 명확히 알려주는 것이 중요

#### 사용 경우

**폴리곤**
- 객체의 윤곽을 정확하게 그려야 할 때
- 객체의 방향이 가로/세로가 아닐 때 (예: 간판의 텍스트가 대각선으로 적혀 있는 경우)

**폴리라인**
- 도로나 강 등의 경계선을 표현할 때

#### 규칙 예시

**폴리곤**: 다른 객체에 겹쳐 있는 경우, 조각난 객체를 각각 그린 후 하나의 그룹으로 지정
- 폴리곤은 경계를 구체적으로 표시하는 방법이므로 바운딩 박스와는 다른 규칙 필요

**폴리라인**: 점선으로 표시된 차선은 각각 다른 폴리라인으로 표기한다
- 점선 차선을 실선으로 라벨링할 경우 노이즈가 다수 포함될 수 있음
- 라벨러마다 결과가 달라질 수 있음 (예: 교차로)

### 키포인트 규칙

#### 고려 사항
키포인트는 정밀하고 섬세한 데이터가 필요한 경우에 사용
- 각 포인트가 빠짐없이 정확하게 찍히도록 안내

#### 규칙 예시
관절의 키포인트는 관절을 원으로 생각했을 때 해당 원의 중심점에 찍는다
- 최대한 정확하고 동일한 위치에 키포인트가 라벨링되도록 규칙 마련
- 라벨러들끼리 싱크를 맞춰야 함
- 오래 걸리는 작업일수록 파일럿으로 해보고 본 구축에 들어가기

## 5. 자연어 처리(NLP) 라벨링

### NLP 라벨링 기법 종류

텍스트 및 음성 데이터를 입력으로 하는 라벨링 기법:

#### 1. 분류 및 태깅 (텍스트/음성 → 태그)
문서 전체 또는 특정 말뭉치의 라벨을 정하는 작업

**분류**
- 주어진 텍스트(문서)의 전체를 주어진 클래스로 라벨링
- 문서를 여럿으로 쪼개어 분류하는 것도 가능하나, 대체로 쪼개는 단위가 큼
- 모든 텍스트가 하나 이상의 클래스에 속해야 함
- 예: 문서 분류, 상품 분류, 이메일 분류

**태깅**
- 주어진 텍스트 내에서 특정 부분을 식별하여 해당 부분에 태그를 라벨링
- 아무 태그에도 속하지 않는 텍스트도 존재할 수 있음
- 예: 형태소 태깅, 주제 기반 감성 분석(ABSA), 개체명 인식(NER)

#### 2. 전사 (음성 → 텍스트)
음성 데이터를 텍스트로 받아적는 작업

**전사의 종류**

**일반 전사**
- 사람이 말한 그대로 문자화하여 전사 (발음 전사)
- 전사 방법이 가장 단순하여 짧은 작업 시간 요구

**이중 전사**
- 한 단어 또는 어절에 대해 두 번 전사
- 발음 전사와 철자 전사(표준어 표기)를 병기
- 예: (구지)/(굳이)

**화자 전사**
- 여러 명의 화자를 구분하기 위한 전사 (노이즈 포함)
- 목소리에 따라 구분

#### 3. 번역 및 요약 (텍스트 → 텍스트)
주어진 텍스트를 다른 텍스트로 변환하는 작업

**특징**
- 원본 텍스트의 의미를 보존하는 다른 형태의 텍스트로 변환
- 입력과 출력 모두 텍스트이기 때문에 특별한 라벨링 툴 불필요
  - 엑셀 시트, 구글 스프레드 시트로도 가능
- 문맥을 정확하게, 그리고 동일한 스타일로 전달하는 번역/요약 생성 필요
- 일정 수준 이상의 언어적 지식을 가진 라벨러 필요

### 분류 및 태깅 규칙

#### 고려 사항
분류나 태깅 모두 주어진 라벨/태그 범주 안에서 어떤 값에 해당하는지를 선택하는 작업

**핵심 원칙**: 범주 간, 그리고 범주 내 라벨 간에 **상호배타적인 관계**를 갖도록 구성

고려해야 할 사항:
- 라벨링/태깅의 대상과 아닌 대상의 구분
- 같은 범주 내의 라벨/태그의 구분
- 우선순위, 계층, 예외 처리

→ Edge case에 신경써서 가이드라인 작성

#### 규칙 예시

**예시 1**: 동일한 태그를 가진 단어가 연속될 경우, 하나의 태그로 라벨링한다
- 단, 동일한 준위가 아닌 상하위 관계를 가지는 단어일 경우 별개로 태깅
- 두 개 단어가 하나의 개체로 라벨링되어야 하는지, 별개의 개체로 라벨링되어야 하는지 상세히 정해야 함

**예시 2**: 둘 이상의 라벨/태그에 속할 경우 이를 최대한 분리하여 표기한다

문장 유형 판단 데이터 예시:
- 뉴스의 특정 문장이 사실형과 추론형에 모두 속하는 경우
  - 만일 문장을 구 또는 절로 쪼개어 태깅할 수 있으면 분리
  - 그렇게 할 수 없는 경우 한 문장에 두 개의 태그를 라벨링

> 💡 하나 → 하나 / 하나 → 둘 이상 ⇒ 모델에 따라 다름, 통일성이 중요!
> 
> **모델 이해도가 높을수록 데이터 구축이 알맞게 이루어짐**

### 전사 규칙

#### 고려 사항
자연어를 받아적는 것이므로 균일한 자연어 처리를 위한 규칙과 기준 필요

**주요 고려사항**
- 전사 단위 및 입력 방법
- 맞춤법: 맞춤법, 띄어쓰기, 방언 처리
- 노이즈 처리: 대표 발화자 외의 모든 소리를 어떻게 전사할 것인지
- 개인정보 비식별화: 어떤 정보를 어떻게 비식별화해야 하는지

#### 맞춤법 규칙 예시

**예시 1**: 축약형 발화의 경우 이중 전사를 통해 표기한다
```
원문: 쨌든 그 일 땜에 글케 된 건 맞아.
전사: (쨌든)/(어쨌든) 그 일 (땜에)/(때문에) (글케)/(그렇게) 된 건 맞아.
```

**예시 2**: 방언은 이중 전사를 통해 표기하며, 가장 유사한 표준어로 표기한다
```
원문: 돈이 웂어도 남한테 아수운 소리는 못하겠다.
전사: 돈이 (웂어도)/(없어도) 남한테 (아수운)/(아쉬운) 소리는 못하겠다.
```

> 💡 이중 전사를 통해 보다 통일성 있으면서 다양한 정보를 포함한 라벨 확보 가능
> 
> **맞춤법 교육을 먼저 하고 전사 진행 → 데이터 퀄리티 향상**

#### 개인정보 비식별화 규칙 예시

**예시 1**: 둘 이상의 동일한 개인정보가 언급될 경우, 나오는 순서대로 끝에 번호를 붙여서 마스킹
```
원문: 그때 철수랑 민수랑 너랑 나랑 갔잖아. 철수도 알고 있지?
전사: 그때 &name1&이랑 &name2&이랑 너랑 나랑 갔잖아. &name1&도 알고 있지?
```
→ 합성 데이터 만들 때 용이

**예시 2**: 주소는 동 단위까지만 전사하고 나머지는 마스킹
```
원문: 홍제동 한양아파트 205동 304호로 배달해주세요.
전사: 홍제동 &address&로 배달해주세요.
```

### 요약 규칙

#### 적용 가능한 규칙
대부분의 전사 규칙을 적용할 수 있으며, 이 외에 요약이라는 문제의 특성상 들어가야 하는 규칙들이 존재

**주요 규칙 요소**
- **요약 형식**: 몇 문장으로 또는 몇 단어 내외로 요약해야 하는지
- **요약 내용**
  - 수정 불가능한 단어와 수정 가능한 단어의 범주
  - 어떤 내용을 필수로 포함시켜야 하는지

#### 규칙 예시

**예시 1**: 모든 문장에는 육하원칙 6가지 요소가 포함되어야 한다

**예시 2**: 각 문장에는 원문에 포함된 핵심 키워드 2개 이상이 사용되어야 한다
- 라벨러마다 요약하는 방식이 다를 수 있으나 이를 최대한 통일시키기 위해 최소한의 규칙 마련

## 6. 라벨링 툴

### 라벨링 툴 개요

**라벨링 툴(Labeling Tools, Annotation Tools)**
효율적인 데이터 라벨링 작업을 위해 사용하는 소프트웨어

#### 주요 기능
- 잘 설계된 GUI 제공 → 직관적, 효율성 향상
- 라벨러 및 검수자를 돕는 부가적인 기능 제공
  - 라벨링 자동화
  - 공동 작업
  - 커뮤니케이션
  - 라벨 품질 검수
  - 워크플로우 커스텀화

### 툴 선정 시 고려사항

#### Quality Control
일관성 있고 정확한 데이터를 생성할 수 있는지

#### Efficiency
시간을 단축하여 효율적으로 데이터를 쉽게 구축할 수 있는지

#### Scalability
여러 작업자가 동시에, 대규모 데이터를 처리할 수 있는지

> 💡 AI Hub 데이터셋의 경우, 상용제품 외의 저작도구는 설치매뉴얼과 함께 다운받을 수 있도록 제공

### 도메인별 라벨링 툴

#### 이미지 라벨링 툴
- **COCO Annotator** (무료)
- **CVAT** (Computer Vision Annotation Tool) (부분유료)
- **Diffgram** (대부분 무료)
- **LabelImg** (무료) - Label Studio에 포함되면서 업데이트 중단
- **LabelMe** (무료)
- **Scale AI** (유료, 무료 평가판 제공)
- **SuperAnnotate** (부분유료)
- **Supervisely** (부분유료)
- **VIA** (VGG Image Annotator) (무료)
- **VoTT** (Visual Object Tagging Tool) (무료) - 업데이트 중단

#### 텍스트 라벨링 툴
- **Brat** (무료)
- **Doccano** (무료)
- **INCEpTION** (무료) - WebAnno의 후신
- **LightTag** (부분유료)
- **Prodigy** (유료)
- **Tagtog** (부분유료)
- **Taguette** (무료)
- **UBIAI** (유료)

#### 다중 도메인 툴
이미지, 영상, 텍스트, 음성 등 여러 도메인을 다루는 툴
- **Label Studio** (무료, 클라우드용은 유료)
  - 이미지, 영상, 텍스트, 음성, 웹사이트, 시계열 등
- **Labelbox** (유료, 무료 평가판 제공)
  - 이미지, 영상, 텍스트, 음성, 의료, 지리
- **Universal Data Tool** (무료)
  - 이미지, 텍스트, PDF, 음성

#### 3D 포인트클라우드 데이터
- **3D-BAT** (무료): 포인트 클라우드에 3D 바운딩 박스로 라벨링
- **LATTE** (무료): 포인트 클라우드에 바운딩 박스로 라벨링
- **Pixano** (무료): 2D, 3D 데이터를 모두 라벨링

#### 시계열 데이터
- **TagAnomaly** (무료): 마이크로소프트사에서 개발한 이상치 분석 및 라벨링 도구
- **Curve** (무료): 바이두에서 개발한 이상치 라벨링 도구

#### 지리 데이터
- **ArcGIS** (유료)
- **QGIS** (무료)
- **Mapbox** (부분유료): 지도를 라벨링하고 지리 정보와 다른 정보를 연동

#### 생물/의료 데이터
- **MedTagger** (무료): 의료영상 데이터를 라벨링하기 위한 협업 도구
- **open-CRAVAT** (무료): 유전체 변이 데이터(VCF)를 라벨링
- **PCGR** (무료): 암 유전체 데이터에서 발생한 변이를 라벨링

### 가이드라인 작성의 핵심 원칙
```
통일성 > 정확성 > 효율성

- 라벨러의 입장에서 이해 가능한 용어 사용
- 정량적 기준 제시 (주관적 판단 배제)
- 실제 사례로 Edge Case 설명
- 처음부터 완성도 있게 작성
```

### 도메인별 라벨링 핵심

**CV (Computer Vision)**
- 통일성과 일관성이 가장 중요
- 노이즈 최소화 원칙
- 객관적이고 정량적인 기준 제시

**NLP (Natural Language Processing)**
- 상호배타적인 라벨/태그 체계 구성
- 이중 전사로 정보 풍부화
- 맞춤법 교육 선행 필수
- 개인정보 비식별화 규칙 명확화

### 라벨링 품질 향상 전략
1. **파일럿 테스트**: 오래 걸리는 작업일수록 파일럿으로 검증
2. **모델 이해도 향상**: 모델 이해도가 높을수록 알맞은 데이터 구축 가능
3. **지속적인 검수**: 라벨링 진행과 검수의 반복적 사이클
4. **가이드라인 버전 관리**: 변경 시 이전 데이터 클렌징 필수
