# Orchestrator

- 다수의 container를 조정하고 관리하는 시스템, 컨테이너의 배포, 스케일링 및 네트워킹을 자동화
- 높은 가용성, 확장성 및 신뢰성을 가진 시스템을 구축하기 위해 container화된 애플리케이션의 복잡한 작업을 간소화

## 중요성

- 복잡성 관리 : 복잡한 서비스의 생명 주기를 관리하고, 여러 컨테이너 간의 의존성을 조정 자동화
- 확장성 : 사용량 증가에 따라 자동으로 리소스를 조정하고, 필요에 따라 서비스를 확장, 축소
- 고가용성 : 서비스의 지속적인 가용성을 보장, 장애 발생 시 자동으로 복구

## 주요 기능

- 자동 배포 및 관리 : 사용자가 정의한 설정에 따라 컨테이너를 자동으로 배포, 실행
- 스케일링 및 로드 밸런싱 : 트래픽의 증가나 감소에 따라 자동으로 컨테이너 수를 조절
- 자동 복구 및 장애 대응 : 오류가 발생한 컨테이너를 자동으로 감지, 필요한 경우 복구 조치
- 서비스 발견 및 네트워킹 : 컨테이너 간의 통신 및 서비스 발견을 관리
- 업데이트 및 롤백 관리 : 애플리케이션 업데이트를 안전하게 관리하고, 필요한 경우 이전 버전으로 롤백

## MLOps에서의 활용

- 대규모 머신러닝 파이프라인 관리
- 실시간 데이터 처리 및 분석
- 다양한 머신러닝 모델의 동시 트레이닝 및 배포
- 대규모 분산 모델 트레이닝

## MLOps에서의 중요성

- 복잡한 워크플로우 관리 : 머신러닝 프로젝트는 데이터 수집, 전처리, 모델 트레이닝, 평가, 배포 등 다양한 단계로 구성, 이러한 과정을 자동화하여 수동으로 작업을 조정하는 복잡성과 오류가능성을 줄임, 자동 스케일링 및 로드 밸런싱 기능을 통해 리소스 사용을 최적화, 필요에 따라 유연하게 리소스를 할당하거나 회수
- 고가용성 및 복구 매커니즘 : 시스템 가용성 높이고 장애가 발생했을 때 빠르게 복구, 머신러닝 시스템의 신뢰성 높임
- CI/CD : 머신러닝 모델의 지속적인 통합과 배포를 지원, 모델이 지속적으로 개선되고 새로운 데이터에 신속하게 적응할 수 있도록 도움

# Appendic: YAML

- YAML : YAML Ain't Markup Language
- 데이터 직렬화 언어
- 구성 파일, 데이터 교환, 설정 파일 등에 널리 사용
- 읽기 쉽고, 쓰기 쉬우며, 프로그래밍 언어 간 데이터 교환에 적합

## 특징

- 가독성 : 인간이 읽기 쉬움
- 계층적 구조 : 들여쓰기
- 다양한 데이터 타입 지원 : 스칼라 타입, 리스트, 맵 등
- 멀티 도큐먼트 지원 : 하나의 파일 내에 여러 문서를 '---'로 구분하여 표현 가능

### 주의 사항

- 들여쓰기 : 공백 들여쓰기 중요(탭 사용 피해야함)
- 데이터 타입 : 자동으로 변환될 수 있음
