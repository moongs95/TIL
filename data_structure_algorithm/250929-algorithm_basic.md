# 알고리즘

- 문제를 해결하기 위한 명령의 집합
- 문제를 해결하기 위해 단계적으로 수행하는 절차

1. 명확성 : 알고리즘의 각 단계는 모호하지 않고 명확해야 한다
2. 유한성 : 알고리즘은 한정된 단계에 종료되어야 한다
3. 입력 : 알고리즘은 0개 이상의 입력이 주어져야 한다
4. 출력 : 알고리즘은 1개 이상의 출력을 생성해야 한다
5. 유효성 : 알고리즘의 각 단계는 수행 가능해야 한다

## 필요성

- 복잡한 문제 -> 순차, 체계적으로 접근하여 쉽게 만들기
- 컴퓨터 자원의 문제
- 코딩 테스트

## 시간 복잡도

- 입력 크기가 무한대로 증가한다고 가정할 때 알고리즘의 성능
- O(n) : 내 알고리즘이 c * g(n) 보단 빠르다
- Ω(n) : 내 알고리즘이 아무리 빨라도 b * g(n)보단 느리다
- 𝜣(n) : O(n) ځΩ(n)
- 세타가 가장 정확하지만, 일반적으로 Big O 를 많이 사용
- 최고 차항의 경향성을 근사하는 방식으로 빠르게 계산

### 종류

- O(1) : 상수시간, N의 크기와 상관 없이 일정한 시간에 계산 => 단순계산, 수학 공식 등
- O(log n) : 로그 시간, 단계가 지날수록 문제의 크기가 줄어드는 경우 => 이분탐색 등
- O(n) : 선형 시간 → 반복문 하나, N의 크기와 비례해서 시간이 증가하는 문제 => 배열의 탐색, 순회 등
- O(n log n) : 선형 로그 시간 => 분할 정복, 이분탐색 + 순회 등의 문제
- O(n^2) : 2차 시간, N의 제곱에 비례하는 시간 복잡도 => 2차원 배열, 행렬, 버블/삽입/선택 정렬
- O(2^n) : 지수 시간, 지수에 비례하는 시간 복잡도 => 순열조합, Brute-force 등

## 공간 복잡도

- 코드가 동작하는 동안 사용하는 메모리 크기
- 고정 공간 : N의 크기과 무관화게 항상 필요하는 공간
- 가변 공간 : N의 크기에 비례해서 변하는 공간

### 최적화

1. 효율적인 자료구조를 선택하여 메모리 사용 최소화
2. 재귀 vs 반복문 -> 메모리가 취약하다면 반복문 선택
3. 미사용 메모리 해제 혹은 재사용
