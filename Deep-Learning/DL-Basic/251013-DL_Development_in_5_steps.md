# 딥러닝의 발전 5단계

- AI/ML/DL 관점에서 크게 5단계로 개발 방법론은 진화
- 세 단계로 나눠서 SW1.0, SW2.0, SW3.0이라고도 부름

## 단계 1. 규칙 기반 프로그래밍(Rule-based programming)

- Input -> Hand-designed program -> Output
- 목표 달성에 필요한 연산 방법을 모두 사람이 고안(SW1.0방식)
- 어떤 계산을 해야 원하는 결과가 나오는지 사람이 다 설계

```text
개와 고양이 사진들 -> 귀의 길이, 코의 색, 코의 길이, 눈의 색 등 -> 고양이
```

## 단계 2. 전통 머신러닝 기법(Conventional Machine Learning)

- Input -> Hand-designed features -> Mapping from features -> Output
- 특징값을 뽑는 방식은 기존처럼 하되, 특징값들로 판별하는 로직은 기계가 스스로 고안(SW1.5방식 : SW1.0과 SW2.0의 Hybrid)

```text
개와 고양이를 구분하는 특징은 사람이 설계 -> 어떤 값들이 나오면 개다! 고양이다! 라고 판단하는 연산은 기계가 설계
```

### 머신러닝 동작법 살펴보기

1. 학습데이터 준비 : 이미지 수집 -> 특징 정의 -> 학습 데이터 생성(숫자로 만들어 줌) -> 라벨링 단계(정답)
2. 모델 학습 : 예측 및 오차(오차를 최소화하는 연산을 찾아내는 것이 핵심 => Try & Error 방식으로 최적의 연산 집합을 찾아냄)

- 최적의 연산 집합은 모든 Try 중에 오차가 제일 작은 것! = 최적의 모델 = 학습 완료된 모델 = 추론 시 사용되는 모델(서비스 사용 시)
- 연산이 결국 모델!

## 단계 3. 딥러닝(Deep Learning)

- Input -> Deep&Wide Neuralnetwork[features -> Mapping from features] -> Output
- 딥러닝부터 출력을 계산하기 위해 모든 연산들을 기계가 고안(SW2.0)
- 모든 걸 기계가 설계 : 특징값 계산, 판별 등
- 엄청나게 많은 연산들의 집합, 자유도가 높으면 오차가 높음 -> 틀(모델구조)을 잡아주면됨
- 입력 데이터가 무엇이냐에 따라 구조를 잡음 ex. CNN, RNN 등
- 딥러닝은 스스로 알아낼 게 더 많으니 더 많은 데이터가 필요!
- 텍스트 데이터 준비과정 : 토근화(의미분석에 용이한 단위인 토큰으로 쪼갬)
- 라벨링은 여전히 사람이 해야함

## 단계 4. 사전학습과 미세조정(Pre-training & Fine-tuning)

- Input -> Pre-trained model -> Fine-tuned model -> Output
- 기존의 문제점 : 분류 대상이 태스크가 바뀔때마다 다른 모델이 필요

```text
개/고양이 구별하는 모델 생성 -> 판다/토끼로 요구사항 변경 -> 개구리/소 -> 개구리/소/토끼
요구사항이 바뀔 때마다 모든 과정을 처음부터 반복해야 함
산업적으로 퍼지는 속도가 더뎌짐
```

### 학습의 2단계

1. Pre-training : 천 개 이상의 동물들 데이터 입력 -> 많은 동물을 구별하는 일반적인 특징을 익히게 학습 -> 분류 연산도 같이 학습 -> 분류 결과는 천 개 이상이 나옴
2. Fine-tuning : 서비스 요구사항이 판다와 토끼 구별(클래스 수 2개) -> 특징 연산은 고정 -> 분류 판단하는 연산을 변경(판다/토끼에 맞춰)

- 여전히 태스크마다 다른 모델이 필요하지만 필요한 데이터 수가 적어지고 개발 속도가 올라가게 됨
- 사전 학습된 모델을 가져오고, 특정 태스크만 구별하고 싶을 때는 모델의 일부만 학습시키면 되서 데이터 수가 적어도됨
- 수많은 데이터 -> 많은 Frozen layers + Training layers -> 분류

#### 텍스트 데이터 관점에서 살펴보기 : GPT1

- Pre-training : 언어의 일반적인 특징을 익히게 한 후 고정(Text -> Features + Mapping from features -> 태스크 정답)
- 인터넷 상의 수많은 데이터를 활용하려면 태스크 정답을 세팅하는 작업이 없어야 훨씬 효율적
- Text -> Features -> 정답(입력 텍스트에서 정답을 만들어 냄)
- 라벨링 없어도 학습이 되는 태스크가 된다면 인터넷의 모든 글이 학습 데이터가 됨
- 사람의 개입 없이 정답을 뽑아냄(비지도 학습)

```text
TASK : 다음 단어 맞추기(언어 모델, Language Model)
-> 과거 몇 단어가 주어졌을 때, 다음 단어는?
```

- 학습 데이터 무한히 생성 가능
- 이런 사전 학습 모델을 가지고 텍스트 분류를 하고 싶다면

```text
TASK : 텍스트 분류(Text Classification)
-> 이 리뷰는 긍정적인가 부정적인가 분류
```

- 분류하는 모델만 Fine-tuning(사람의 개입으로 긍정/부정 라벨링)
- GPT1, 2, 3 => 사이즈를 올리면 성능이 올라간다! GPT3 : 175B params

## 단계 5. 초거대 모델과 제로샷/퓨샷(Big Model & Zero/Few shot)

- Input -> Big model -> zero/few shot -> Output
- why GPT3? : in-context learning
- 학습이 아님
- 태스크 별로 별도 모델 필요 없음
- 태스크에 맞는 데이터 모을 필요 없음
- Text(태스크 설명 포함) -> Features -> 태스크 정답
- 텍스트 분류와 같은 fit한 모델이 필요가 없고 태스크에 맞는 데이터를 모을 필요도 없고 사전 학습된 모델로 모든게 가능
- 입력 text에 태스크 설명을 포함했더니 스스로 학습해서 알아냄(in-context learning)
- 특정 모델 크기 이상이 되면 in-context learning이 가능해짐
- fine-tuning 없어도 성능이 더 뛰어남
- zero-shot : 태스크 설명 예시가 0개(shot은 태스크 예제의 수) -> one-shot, few-shot(k=64)

```text
번역 예시
1. Zero-shot은 태스크 설명만 있고 바로 지시
	한국어로 바꾸시오
	cheese => ?
2. One-shot은 예제 하나 추가
	한국어로 바꾸시오
	apple => 사과
	cheese => ?
3. Few-shot은 예제 여러 개 추가
	한국어로 바꾸시오
	apple => 사과
	candy => 사탕
	ball => 공
	cheese => ?
```
