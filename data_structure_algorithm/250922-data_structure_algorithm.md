# 자료구조와 알고리즘

## 알고리즘

### 개념

- 컴퓨터로 문제를 풀기 위한 단계적인 절차

### 조건

- 입력 : 0개 이상의 입력
- 출력 : 1개 이상의 출력
- 명백성 : 명령어는 명확
- 유한성 : 한정된 수 단계 후에는 반드시 종료
- 유효성 : 명령어는 실행 가능한 연산

### 기술 방법

- 영어나 한국어와 같은 자연어
- 흐름도
- 의사코드 프로그래밍 언어

## 추상 자료형

- 자료형 : 데이터의 종류
- 데이터 집합과 연산의 집합
- 추상 데이터 타입(ADT: Abstract Data Type) : 데이터 타입을 추상적(수학적)으로 정의, 데이터나 연산이 무엇인가는 정의되지만 데이터나 연산을 어떻게 컴퓨터 상에서 구현할 것인지는 정의되지 않음.
- 추상화 -> 정보은닉기법 -> 추상 자료형
- 추상화 : 사용자에게 중요한 정보는 강조되고 반면 중요하지 않은 구현 세부 사항은 제거되는 것
- 객체 : 추상 데이터 타입에 속하는 객체가 정의
- 연산 : 객체들 사이의 연산이 정의, 추상 데이터 타입과 외부를 연결하는 인터페이스의 역할
- 함수 : 실질적으로 뭔가가 동작되는 중요한 중추적 역할

## 알고리즘 성능분석

- 수행 시간 측정
- 알고리즘의 복잡도 분석

### 복잡도 분석

- 시간 복잡도는 알고리즘을 이루고 있는 연산들이 몇 번이나 수행되는지를 숫자로 표시
- 시간 복잡도, 공간 복잡도
- 입력의 개수를 고려하여 n에 대한 함수로 나타냄

### 빅오 표기법

- 연산의 횟수를 대략적(점근적)으로 표기한 것
- 자료의 개수가 많은 경우에는 차수가 가장 큰 항이 가장 영향을 크게 미치고 다른 항들은 상대적으로 무시
- 빅오는 함수의 상한을 표시

### 그 외 표기법

- 빅오메가 표기법 : 하한을 표시
- 빅세타 표기법 : 하한인 동시에 하한을 표시

### 최선, 평균, 최악의 경우

- 최선 : 수행 시간 가장 빠른 경우 - 의미가 없는 경우가 많음
- 평균 : 평균적인 시간 - 계산하기 상당히 어려움
- 최악 : 수행 시간 가장 느린 경우 - 가장 널리 사용, 계산하기 쉽고 응용에 따라 중요한 의미 가짐
