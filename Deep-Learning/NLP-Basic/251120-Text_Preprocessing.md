# 📘 텍스트 전처리(Text Preprocessing) 완전 정리

텍스트 전처리는 **자연어 처리 성능을 좌우하는 핵심 과정**
모델 구조가 아무리 좋아도 **입력된 텍스트 품질이 낮으면 성능도 낮게 나온다.**

---

# 1. 전처리(Preprocessing) 개요

## 1.1 전처리의 필요성
- 모델이 어떤 데이터를 보느냐에 따라 성능이 크게 달라짐  
- 대규모 딥러닝 시대에도 여전히 **데이터 품질은 성능을 결정**
- 전처리는 다음과 같은 작업을 포함함:
  - HTML 태그/특수문자 제거
  - 중복 제거
  - 개인정보 제거
  - 토큰화
  - 불필요한 단어 제거
  - 정규화

## 1.2 기본 Preprocessing Pipeline

```text
문서 → 토큰화 → 텍스트 정제 → 불용어 제거 → 어휘 정규화 → 단어 집합 생성
```

---

# 2. 토큰화(Tokenization)

## 2.1 토큰화란?
- 텍스트를 **의미 단위(Token)** 로 나누는 과정  
- 토큰 단위는 다양할 수 있음:
  - Character (문자 단위)
  - Word (단어 단위)
  - Subword (부분 단어 단위)
  - Morpheme (형태소 단위)

### 토큰화 종류
| 종류 | 설명 |
|------|------|
| Sentence Tokenization | 문장 분리 |
| Word Tokenization | 단어 분리(구두점 분리 포함) |
| Subword Tokenization | BPE, Unigram 등 |
| 형태소 기반 Tokenization | 한국어 처리에 필수 |

---

# 2.2 토큰화 시 고려할 점
1. 구두점/특수문자를 무조건 제거하면 의미 손실 가능  
2. 줄임말, 붙여 쓰기 처리 필요  
3. 단순히 마침표로 문장 분리 불가  
   - 예: `Dr. Kwon`, `U.S.A.`

---

# 2.3 한국어 토큰화가 어려운 이유
- 한국어는 **교착어** → 조사가 단어에 붙어서 의미 변화  
- 띄어쓰기가 불규칙  
- 하나의 어절에 여러 형태소가 포함  
→ 형태소 기반 분석이 필요

---

# 2.4 대표 Tokenization Tools

## KoNLPy (한국어)
- `morphs()` : 형태소 추출  
- `pos()` : 품사 태깅  
- `nouns()` : 명사 추출  
- Twitter, Komoran, Mecab 등 다양한 분석기 제공

## SentencePiece (Google)
- BPE · Unigram 기반 Subword tokenizer  
- 언어 독립적 방식

## Huggingface Tokenizers
- BERT, GPT 등 사전학습 모델의 토크나이저 제공  
- 빠르고 병렬 처리 가능  
- Subword vocabulary 자동 관리

---

# 3. 텍스트 정제(Cleansing)

## 3.1 텍스트 정제란?
코퍼스에서 **노이즈(의미 없는 텍스트)를 제거하여 분석 가능 상태**로 만드는 과정

### 주요 작업
- 특수문자 제거
- HTML 태그 제거
- 중복 문장/중복 공백 제거
- 정규표현식을 이용한 패턴 정리
- 소문자 변환(영어 기준)
- 불필요한 단어 제거

---

# 4. 불용어(Stop Words)

## 4.1 불용어란?
- 자주 등장하지만 분석에는 의미 없는 단어  
  - 예: “그리고”, “그러나”, “저는”, “이것은”  
- 목적에 따라 불용어 목록을 **직접 정의**하는 것이 중요

예: 감성 분석  
→ “너무”, “정말” 같은 단어는 중요한 의미를 가지므로 제거하면 안 됨

---

# 5. 정규화(Normalization)

정규화는 텍스트를 **통일성 있게 변환하여 변형을 줄이는 작업**

## 5.1 어근 추출(Stemming)
- 형태를 단순히 잘라서 어근만 남김  
- 포터 알고리즘 등 규칙 기반  
- 원형이 훼손될 수 있음 (aggressive)

예:  
- `studying → study`  
- `studies → studi` (잘못된 형태 가능)

## 5.2 표제어 추출(Lemmatization)
- 품사 정보를 이용하여 **단어의 원형(lemma)** 로 변환  
- Stemming 보다 정확  
- 형태학적 분석을 기반으로 함

예:
- `studies → study`  
- `better → good`

---

# 6. 편집거리(Edit Distance)

## 6.1 Levenshtein Distance
두 문자열을 동일하게 만들기 위한 최소 연산 횟수  
- **삽입(insert)**  
- **삭제(delete)**  
- **치환(substitution)**

예시  
- “점심을먹자” → “점심먹자” : 삭제 1회  
- “점심먹자” → “점심을먹자” : 삽입 1회  
- “점심먹자” → “점심먹장” : 치환 1회  

→ 회수(거리)가 낮을수록 두 문장은 유사

활용:
- 맞춤법 검사  
- 오타 교정  
- 문자열 유사도 계산

---

# 7. 정규표현식(Regex)

## 7.1 정규표현식이란?
특정 규칙을 가진 문자열 집합을 표현하는 형식 언어

### 활용
- 원하는 패턴만 추출  
- 불필요한 데이터 제거  
- 문자 치환, 패턴 검색, 데이터 정규화  
- Python에서 `re` 라이브러리 사용

### 예시
- 이메일 패턴 찾기  
- 특수문자 제거  
- 한글/영문/숫자만 남기기  

---

# 🔚 결론

텍스트 전처리는 NLP의 **첫 번째이자 가장 중요한 단계**

- 품질 높은 데이터 확보  
- 최적의 토큰화  
- 불용어/정규화 기준 설정  
- 적절한 정제 및 필터링  
- 언어 특성에 맞는 처리 (특히 한국어)

이러한 전처리 과정이  
👉 모델 성능  
👉 학습 효율  
👉 추론 안정성  
을 크게 향상시킴
