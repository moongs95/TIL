# 역색인과 형태소 분석기

## 1. 역색인과 형태소 분석기

### 1.1 문서 역색인

#### 색인 (Indexing)

**정의**:
- **키워드를 입력했을 때 문서를 빠르고 효율적으로 검색하기 위해 문서 집합을 미리 가공하는 작업**

**과정**:
- 문서를 검색어 토큰들로 변환
- 데이터가 빠르게 추출될 수 있는 구조로 저장

---

#### 검색엔진의 색인 구조 - 역색인 (Inverted Index)

**구조**:
- **단어가 key 값**이 되고, **그 단어가 존재하는 문서들이 value**
- 특정 토큰이 어떤 문서와 연관되어 있는지 매핑되어 있음

**장점**:
- 관련된 문서를 찾는 과정에서 **키워드에 해당하는 문서만 추출**할 수 있음
- **검색 속도가 빠름**

---

#### 역색인을 활용하는 일반적인 색인 단계

**5단계 프로세스**:

**1. 텍스트 추출**
```
다양한 형식을 가진 문서에서 텍스트를 추출
```

**2. 토큰 추출**
```
자연어인 텍스트를 단어 단위로 분해
→ 형태소 분석기 사용
```

**3. 불용어 (Stop-word) 처리**
```
의미를 가지지 않는 관용어, 불용어 등을 제거
```

**4. 정규화**
```
표제어 및 어간 추출
```

**5. 역색인 생성**
```
최종 역색인 데이터 구조 생성
```

---

### 1.2 형태소 분석기

#### 토큰화 (Tokenization)

**정의**:
- **문서 또는 질의를 정보의 기본 단위인 단어(토큰)로 나누는 과정**

**역할**:
- **문서의 각 토큰**: 역색인 데이터 구조에 저장될 key로 사용
- **질의의 각 토큰**: 역색인 저장소로부터 탐색을 위한 key로 사용

---

#### 성능 최적화를 위한 추가 정보

**필요한 정보**:

**1. Stop-word 또는 품사 정보**
```
목적: 검색 성능에 영향이 거의 없지만 메모리와 연산 비용에 부하를 주는 단어 제거
예시: 한국어의 경우 주로 조사
```

**2. Lemmatization (표제어 추출)**
```
목적: 단어의 표제어(기본형) 추출
예시: 'running' → 'run'
```

**3. Stemming (어간 추출)**
```
목적: 용언의 어간 추출
예시: '먹었다' → '먹'
```

**4. 복합 명사 정보**
```
예시: 삼성전자 → 삼성 + 전자
```

**5. 동의어 정보**
```
예시: NH, 농협, 농업협동조합
```

---

#### 토크나이저 종류

**1. 공백 기반 토크나이저 (Whitespace Tokenizer)**
```
방법: 텍스트를 공백(스페이스, 탭, 줄바꿈 등)을 기준으로 분리

장점: 대부분의 서유럽 언어에서 효과적

단점: 복합어나 구, 문장부호에 대해서 취약점 있음
```

**2. 규칙 기반 토크나이저 (Rule-based Tokenizer)**
```
방법: 정규 표현식이나 특정 규칙을 이용하여 텍스트를 분리
```

**3. 사전 기반 토크나이저 (Dictionary-based Tokenizer)**
```
방법: 미리 정의된 단어 사전을 사용하여 텍스트를 분리

적용: 언어의 구조가 복잡하거나 공백으로 단어를 구분하기 어려운 언어
예시: 한국어, 중국어, 일본어
```

**4. 서브워드 토크나이저 (Subword Tokenizer)**
```
방법: 단어를 더 작은 단위(서브워드)로 분리

알고리즘:
- BPE (Byte Pair Encoding)
- WordPiece
- SentencePiece
```

---

#### 한국어 형태소 분석 이슈

**한국어의 특성**:

**1. 교착어**
```
정의: 하나의 어근에 여러 형태소가 결합하여 새로운 의미나 문법적 기능을 나타내는 언어
```

```
특징: 시제, 존댓말, 부정 등이 어미를 통해 표현
```

**3. 복합명사와 조사**
```
특징: 복합명사가 흔하며, 명사는 주로 조사와 붙어서 사용됨
```

**4. 중의성 해소의 필요성**

```
문제: 동일한 철자의 다른 의미를 가지는 단어가 흔함

```

# Query-Document Relevance (질의-문서 관련성)

## 1. Retrieval 모델

### 1.1 Boolean 모델

#### 개념

**정의**:
- **질의는 Boolean 형식으로 표현**되고, **문서는 단어들의 집합**으로 표현

**특징**:
- Retrieval 모델 중 **가장 단순한 검색 모델**
- 단어들의 **순서 및 중요도를 고려하지 않음**

---

#### 작동 방식

**질의 표현**:
- Boolean 형식으로 표현되는 질의를 통해 **조건에 맞는 문서 추출**
- AND, OR, NOT과 같은 논리 연산들을 이용
- 정확한 논리적 의미를 가짐

**결과**:
- 모델은 Boolean 수식을 만족하는 모든 문서를 반환

---

#### Boolean 모델의 특징 및 한계점

**한계점**:

**1. 자연어 사용 불가**
```
❌ 질의에 자연어를 그대로 사용할 수 없음
❌ Boolean 연산을 위한 문법을 따라야 함
```

**2. 낮은 성능**
```
❌ 단어의 순서 및 중요도를 고려하지 않기 때문에 성능이 낮음
```

**3. 순위 부재**
```
❌ 추출된 결과에 대한 순위를 매길 수 없음 (0 or 1)
```

**4. 결과 양의 불균형**
```
❌ 추출된 결과가 너무 많거나 적을 수 있음
```

**결론**:
- 따라서, **Boolean model을 단독으로 사용하는 경우는 일반적으로 거의 없음**

---

### 1.2 Vector Space 모델

#### 개념

**정의**:
- **질의와 문서를 n차원의 벡터 공간으로 표현**
- **질의 벡터와 문서 벡터 사이의 유사도를 측정**

**특징**:
- **IR 시스템에서 가장 잘 알려지고 넓게 사용되는 모델**

---

#### 문서 표현

**방법**:
1. 문서를 구성하는 **단어 기준의 벡터 형태로 표현**
2. **단어들에 가중치를 부여**하여 문서 내의 각 단어들마다 중요한 정도를 수치화
3. 벡터를 구성하는 **각각의 차원**은 **개별 단어에 대응**
4. 해당 차원은 **대응되는 단어의 가중치 값**을 가지게 됨

---

#### 질의 표현

**방법**:
- **질의 표현 = 문서와 같은 방식으로 표현됨**

---

#### 유사도 계산

**방법**:
- **질의 벡터**와 **문서 벡터**들의 **유사도를 계산**
- **문서 간 순위**를 매김
- **Sparse vector를 사용하는 선형대수 문제**로 볼 수 있음

---

#### TF-IDF (Term Frequency - Inverse Document Frequency)

**정의**:
- 문서를 사용된 단어의 벡터로 나타냄
- **단어가 얼마나 반복되는지**와 **얼마나 자주 사용되는 단어인지**에 따라 점수 산출

**목적**:
- **여러 문서로 이루어진 문서 집합**이 있을 때
- **어떤 단어가 특정 문서 내에서 얼마나 중요한 것인지를 나타내는 통계적 수치**

**공식**:
```
TF-IDF(t, d, D) = TF(t, d) × IDF(t, D)
```

---

#### TF (Term Frequency) - 문서 내의 단어에 대한 가중치

**정의**:
- **TF(t, d): 문서 내에서 단어의 빈도**
- 특정 문서 d에서 단어 t가 등장한 횟수를 나타냄

**원리**:
- 해당 문서에 **중요한, 핵심적인** 의미를 가지는 단어일수록
- 해당 단어는 **문서에서 자주 등장할 확률이 높음**
- 따라서 **TF가 높을수록 해당 단어는 해당 문서에서 중요한 의미를 가질 확률이 높음**

**공식**:
```
TF(t, d) = 문서 d에서 단어 t가 등장한 횟수 / 문서 d에 등장한 모든 단어의 수
```

---

#### IDF (Inverse Document Frequency) - 개별 단어의 중요도

**DF (Document Frequency)**:
- **단어 t를 포함하는 문서의 빈도**
- 특정 단어 t가 등장한 문서의 수

**IDF (Inverse Document Frequency)**:
- **역 문서 빈도**
- DF의 **역수**에 **로그**를 취함
- 즉, DF에 반비례하는 수를 나타냄
- 많은 문서에 공통으로 나타나는 단어는 중요도가 낮음

**공식**:
```
IDF(t, D) = log(총 문서의 개수 / 단어 t를 포함하는 문서의 수)
```

---

#### Vector Space 모델의 특징 및 한계점

**한계점**:

**1. 단어 철자 수준에서의 매칭 기반**
```
❌ 비슷한 의미를 갖고 있는 문서들일지라도
   사용된 단어(철자)가 다르면 연관성을 갖지 않게 됨
```

**2. 단어 순서 무시**
```
❌ 단어들이 출현하는 순서가 무시됨
❌ 맥락상의 의미를 충분히 반영하지 못함
```

**3. 파라미터 최적화 필요**
```
❌ TF-IDF 알고리즘 적용 시 파라미터를 최적화할 필요
❌ 비용과 시행착오가 수반됨
❌ 동적으로 변하는 데이터에 따른 TF-IDF 알고리즘 내의 상수 재조정이 주기적으로 필요
   (IDF는 문서 개수를 기반으로 하기 때문)
```

---

### 1.3 Probabilistic 모델

#### 개념

**정의**:
- **Probability Theory (확률 이론)에 기반한 Retrieval 모델**

**접근 방식**:
- Retrieval이 본질적으로 **불확실성**을 내포하고 있다고 보고 접근

**불확실성의 종류**:
1. 질의의 표현 형태가 내포하고 있는 불확실성
2. 문서의 표현 형태가 내포하고 있는 불확실성
3. 질의에 적합한 문서 매칭하기 위한 평가 방법의 불확실성

---

#### 작동 방식

**Ranking**:
- **Query-document relevance의 확률값에 따라 ranking estimate**

**Estimation**:
- 측정 가능한 통계 자료를 활용
- TF, IDF, document length

**계산 최적화**:
- 효율적인 계산을 위해 **log-odds를 구함**
- VSM과 이론적인 접근은 다르지만 유사한 결과로 나타남

---

#### Binary Independence Model (BIM)

**특징**:

**1. Binary term weights**
```
- 질의에 나오는 단어만 relevance를 결정 (0/1)
- 개별 term의 중요도는 고려하지 않음
```

**2. 독립성 가정**
```
- 문서의 모든 단어들은 서로 독립
- (실제로는 독립적이지 않은 경우도 많음, 예: 복합명사)
```

---

#### BIM Extensions - term frequency 고려

**1. Two Poisson**
```
가정: 모든 문서의 길이가 동일하다고 가정
유사: VSM에서 기본 TF 사용하는 것과 유사
```

**2. BM11**
```
개선: 문서 길이가 다른 것을 고려
유사: VSM에서 length-normalized TF 사용하는 것과 유사
```

**3. BM25**
```
개선:
- BM11에서 문서 길이가 너무 긴 경우 손해 보는 것 보완
- 문서가 너무 짧을 때 이득 보는 것을 보완

유사: VSM에서 length-normalized TF에 log를 취한 것과 유사
```

---

#### BM25 (Best Match 25)

**정의**:
- 검색 엔진에서 TF-IDF와 함께 **가장 일반적**으로 사용되는 알고리즘
- **기존 TF-IDF 알고리즘을 변형시켜 성능을 개선**한 것과 동일한 효과

---

#### BM25 – TF 관점의 개선 사항

**문제점**:
```
TF-IDF: 중요도가 떨어지는 단어임에도 해당 문서에서 단어의 개수가 많으면 중요한 단어로 인식됨
예시: a, an, the, are, is, ...
```

**해결책**:
```
BM25: 한 문서에 검색어가 많이 출현하면 높은 점수를 부여하지만
      한계치를 넘어가면 더 이상 높은 점수를 부여하지 않음
      (포화 함수 적용)
```

---

#### BM25 – IDF 관점의 개선 사항

**문제점**:
```
일반적으로 불용어는 모든 문서에 자주 등장하기 때문에 낮은 점수를 가짐

TF-IDF: 불용어를 매우 많이 포함하는 문서가 몇 개 있을 때
        TF 값이 커져 불용어를 많이 포함한 문서에 높은 점수가 부여됨
```

**해결책**:
```
BM25: 단어가 출현한 문서 수가 많을수록 낮은 점수를 반영
      한계치가 넘어가면 더욱 더 낮은 점수를 부여
```

---

#### BM25 – 문서 길이 관점의 개선 사항

**개선**:
- **문서의 평균 길이를 계산에 사용**
- 문서의 길이가 검색 점수에 영향을 덜 미치도록 함

---

## 2. Document Quality에 대한 고려

### 2.1 추가적인 Ranking 고려 사항

#### 문제점

**Retrieval 모델의 한계**:
- 문서 자체의 품질에 상관없이 **쿼리와의 적합도만을 고려**

**현실**:
- **문서의 품질이 매우 중요한 고려 사항**

---

#### 주요 이슈

**1. Garbage 문서의 방대한 생성**
```
문제: 저품질 문서가 많이 생성됨
```

**2. 불법 복제, 스팸 등의 이슈**
```
문제: 악의적인 문서들이 존재
```

**3. 시의성에 따른 문서 가치 변화**
```
예시: 뉴스 문서의 경우 시의성이 강함
```

---

### 2.2 주요 Ranking Factors

#### PageRank

**개념**:
- **하이퍼링크를 이용해 웹 페이지의 중요도를 측정**
- 일반 문서보다는 **웹 페이지**나 **논문 자료** 등에 유용

**방법**:
- Web을 **directed graph**로 간주
- 노드는 웹페이지, 링크는 하이퍼링크로 표현

**점수 계산**:
- 링크 정보를 이용하여 노드마다 점수를 매김
- **많은 링크를 받는 페이지**
- **높은 점수의 페이지로부터 링크를 받는 페이지**

---

#### Recency (최신성)

**정의**:
- **최근**에 게시되었거나 업데이트된 문서에 **순위를 높게** 측정
- 문서 집합의 종류에 따라 적합한 계산식 선정 필요

**계산식 예시**:

**1. Time Decay Score (시간 감쇠 점수)**
```
1 / (1 + age_in_days)
```

**2. Logarithmic Decay Score (로그 감쇠 점수)**
```
1 / log(1 + age_in_days)
```

**3. 임계치 기반**
```python
if age_in_days <= 30:
    recency_score = 1 - (age_in_days / 30)
else:
    recency_score = 0
```

---

#### Spam Score (스팸 점수)

**주요 요소**:

**1. 키워드 스터핑 (Keyword Stuffing)**
```
문제: 문서 내에서 특정 키워드가 비정상적으로 많이 사용되는 경우
```

**2. 저품질의 인바운드 링크**
```
문제: 스팸 사이트나 저품질 사이트에서 오는 링크의 수와 품질
```

**3. 과도한 외부 링크**
```
문제: 문서가 과도하게 다른 사이트로 링크하는 경우
     특히 링크된 사이트들이 저품질이거나 관련성이 낮은 경우
```

**4. 메타 태그 남용**
```
문제: 광고성 또는 낚시성 태그 남용
```

**5. 콘텐츠 품질**
```
평가: 문법적 오류, 표절, 페이지 권위 점수 등
```

**목적**:
- **문서 품질 정량화**

---

## 3. Relevance Feedback (관련성 피드백)

### 3.1 Relevance Feedback 이해

#### 필요한 이유

**Retrieval 모델의 한계**:
```
문제:
- 문서에 대해 단어(토큰)의 통계 정보 이외의 요소를 무시
- 성능상의 한계로 나타남

가정:
- 모든 문서가 특별히 문제를 가지지 않는 이상적인 문서임을 가정
- 현실적으로 이 가정은 맞지 않음
- 문서의 quality 계산도 처음부터 완벽하게 이루어질 수 없음
```

**사용자 선호의 변화**:
```
문제:
- 사용자의 선호는 시간에 따라 변해감
- 외부적인 이벤트 또는 점진적인 추세 등에 따라 변화
- 사용자가 특정 쿼리에 대해 적합하다고 판단하는 문서들이 변함

해결:
- 실제 서비스를 운영하면서 사용자들이 남기는 feedback 정보를 통해 ranking을 최적화할 수 있음
```

---

### 3.2 IRF의 적용

#### 문제점

**명시적 피드백의 어려움**:
- 일반적인 검색 시스템에서 Relevance Feedback을 사용자에게 강요하기 힘듦

---

#### 해결책: Implicit Relevance Feedback (IRF)

**방법**:
- 명시적인 relevance feedback 대신
- **사용자 action 정보를 활용한 IRF 활용**

**수집 정보**:
- **클릭 비율**
- **검색 기록**
- **페이지 체류 시간** 등

**주의사항**:
- 사용자 프라이버시 고려 및 개인 정보 사용 동의 필요

---

#### IRF 적용 방법

**Ranking에 반영**:
```
Retrieval 모델에 기반한 ranking function에 추가로 IRF 가중치를 반영하여 ranking 계산
```

**DB 유지**:
```
키워드-문서-IRF_score triplet을 포함하는 DB 유지
```

---

#### Relevance Feedback 적용 시 고려사항

**1. 편향성 문제**
```
⚠️ Ranking에서 IRF의 가중치가 높아지면 편향성이 생길 수 있음
⚠️ 검색 결과의 다양성이 줄어들 수 있음

원인:
- 한 번 높으면 상위 노출로 인해 계속 높을 수 있음
- ⇒ 편향!
```

**2. 지속적인 최적화**
```
필요:
- IRF DB 운영
- 지속적인 최적화 필요
```

## 전체 요약

### Retrieval 모델 비교

| 모델 | 특징 | 장점 | 단점 |
|------|------|------|------|
| **Boolean** | 0/1 매칭 | 간단함 | 순위 없음, 성능 낮음 |
| **Vector Space** | 벡터 유사도 | 순위 가능, 널리 사용 | 단어 순서 무시 |
| **Probabilistic** | 확률 기반 | 이론적 근거 | 복잡함 |

---

### 가중치 알고리즘 비교

| 알고리즘 | 개선 사항 | 특징 |
|----------|----------|------|
| **TF-IDF** | 기본 | 단어 빈도 × 역문서 빈도 |
| **BM25** | TF-IDF 개선 | 포화 함수, 문서 길이 정규화 |

---

### BM25의 3가지 개선
```
1. TF 개선: 포화 함수 적용 (한계치 이상 더 증가 안 함)
2. IDF 개선: 불용어 처리 강화
3. 문서 길이 정규화: 평균 길이 고려
```

---

### 문서 품질 평가 요소
```
1. PageRank: 링크 구조 분석
2. Recency: 최신성 반영
3. Spam Score: 스팸 문서 필터링
4. IRF: 사용자 피드백 반영
```

---

### 한국어 형태소 분석의 도전
```
1. 교착어 특성
2. 복합명사 처리
3. 조사 처리
4. 어간/어미 분리
5. 중의성 해소
```

---

### 색인 과정
```
1. 텍스트 추출
   ↓
2. 토큰 추출 (형태소 분석)
   ↓
3. 불용어 처리
   ↓
4. 정규화
   ↓
5. 역색인 생성
```

---

### 최종 Ranking 공식
```
Final Score = Retrieval Score × PageRank × Recency × (1 - Spam Score) × IRF Weight
```

## 주요 개념 정리

### 역색인 (Inverted Index)
```
정의: 단어 → 문서 매핑 구조
목적: 빠른 검색
구조: Key(단어) → Value(문서 리스트)
```

### TF-IDF
```
TF (Term Frequency): 문서 내 단어 빈도
IDF (Inverse Document Frequency): 역문서 빈도
공식: TF × IDF
```

### BM25
```
정의: TF-IDF 개선 버전
특징: 포화 함수, 문서 길이 정규화
용도: 현대 검색 엔진의 표준
```

### PageRank
```
정의: 링크 기반 중요도 계산
원리: 중요한 페이지로부터 링크받으면 중요
개발: 구글의 핵심 알고리즘
```

### IRF (Implicit Relevance Feedback)
```
정의: 암묵적 관련성 피드백
수집: 클릭률, 체류 시간, 검색 기록
목적: 실제 사용자 선호도 반영
```

## 실전 활용 가이드

### 검색 시스템 구축 순서
```
1. 형태소 분석기 선택
   - 한국어: Nori, 은전한닢
   - 영어: Standard Analyzer

   - Elasticsearch, Solr 등 활용

3. Retrieval 모델 선택
   - BM25 (추천)
   - TF-IDF (간단한 경우)

4. 문서 품질 요소 추가
   - PageRank
   - Recency
   - Spam Score

5. IRF 시스템 구축
   - 사용자 행동 로깅
   - 피드백 점수 계산
   - 주기적 업데이트

6. 모니터링 및 최적화
   - 검색 품질 평가
   - 파라미터 튜닝
   - A/B 테스트
```

---

### 상황별 모델 선택

**단순 키워드 검색**:
```
→ BM25 + 역색인
```

**웹 검색 엔진**:
```
→ BM25 + PageRank + Recency + Spam Filter
```

**뉴스 검색**:
```
→ BM25 + Recency (높은 가중치)
```

**학술 논문 검색**:
```
→ BM25 + Citation Count (PageRank 변형)
```

**전자상거래 검색**:
```
→ BM25 + IRF (클릭률, 구매율)
```
