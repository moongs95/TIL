# 검색엔진 발전 과정

## 1. 도전 과제

### 1.1 문제 정의

#### IR (Information Retrieval, 정보 검색)

**정의**:
- **큰 규모의 비정형 텍스트 문서 집합으로부터**
- **원하는 조건의 질의(키워드 또는 텍스트)를 통해**
- **적합한 문서를 추출하는 과정**

**필요성**:
- 인터넷이나 로컬 저장소에 축적되는 방대한 정보 속에서
- 내가 필요로 하는 정보를 찾는 과정은 필수적인 작업

---

### 1.2 속도와 품질

**핵심 요구사항**:
```
방대한 문서에서 질의에 가장 적합한 문서를 빠르게 추출해야 함
```

---

#### 속도 관련 이슈

**질의(Query) 관련**:
```
1. 최대 1초 이내에 가능한가?
2. 질의가 여러 단어인 경우는?
3. 필터링 조건이 추가되면?
4. 트래픽이 많아지면?
```

**문서 저장소 관련**:
```
1. 문서의 양이 극단적으로 커진다면?
2. 문서 유입에 대한 실시간 대응이 필요하다면?
3. 문서가 삭제 또는 업데이트된다면?
```

---

#### 품질 관련 이슈

**정렬된 문서 관련**:
```
1. 질의와의 적합도를 어떻게 수치화할 수 있을까?
2. 문서 자체의 품질 정보도 고려할 수 있을까?
3. 사용자들의 피드백도 반영할 수 있을까?
```

---

## 2. 데이터 구조와 알고리즘

### 2.1 역색인 (Inverted Index)

#### 개념

**기존 방식**:
```
문서 → 어떤 단어가 들어있는지
```

**역색인 방식**:
```
단어 → 어떤 문서가 연결되어 있는지
```

**핵심**:
- **문서에 어떤 단어가 들어있는지가 아니라**
- **단어에 어떤 문서가 연결되어 있는지를 저장!**

---

#### 역색인 데이터 구조 예시
```
Term (단어)  |  Documents (문서 ID)
─────────────┼──────────────────────
문서          |  1, 2, 3
집합          |  1
질의          |  1
적합          |  1
추출          |  1, 3
역색인        |  2
...          |  ...
```

**장점**:
- 특정 단어가 포함된 문서를 빠르게 찾을 수 있음
- 검색 속도 대폭 향상

---

### 2.2 랭킹 (Ranking)

#### 랭킹의 필요성

**문제**:
```
사용자가 많이 추출된 문서를 다 읽어볼 시간이 없음
```

**해결책**:
```
우선순위화해서 몇 개만 알려줘야 함
→ Ranking의 필요성
```

**정의**:
- **질의와 문서의 적합도를 계산하는 알고리즘**

---

#### 랭킹 요소

**1. 질의와 문서와의 유사도**
```
정의: 질의와 문서의 관계에서 나오는 연관도 또는 유사도 점수

알고리즘:
- TF-IDF
- BM25
```

**2. 문서 자체의 품질**
```
정의: 질의와 독립적인 문서 자체의 품질 점수

지표:
- PageRank (페이지 순위)
- Spam Score (스팸 점수)
- Recency (최신성, 시의성 반영)
```

**3. Relevance Feedback (관련성 피드백)**
```
방법: 주로 Implicit Relevance Feedback 사용

지표:
- 사용자 클릭 비율
- 페이지 체류 시간
```

### 3.1 성능 최적화

#### 지속적인 최적화 필요성

**변화하는 요소**:
```
1. 문서가 바뀜
2. 사람들의 관심사나 습관이 바뀜
3. 심지어 언어조차 변해감
```

---

#### 주요 이슈

**1. 형태소 분석기 (Morphological Analyzer)**
```
문제: 역색인 사용 → 언어가 계속 바뀜
질문: 형태소 분석기의 유지/보수 비용을 줄이거나 제거할 수 없을까?
```

**2. 랭킹 모델링**
```
문제: 선호도 계속 변화, 최신성 반영 필요
질문: 랭킹 모델링 비용을 최소화할 수 없을까?
```

---

### 3.2 컨텍스트의 활용

#### 인터페이스의 한계

**기존 방식**:
```
검색창에 텍스트 입력 → 결과 확인 → 반복
```

**개선 방향**:
```
1. 키워드 매칭을 넘어 자연어로 편하게 질의할 수 없을까?
2. 개인화를 통한 최적화가 가능한가?
3. Chat 형식으로 대화할 수 없을까?
```

## 4. 인공신경망의 적용

### 4.1 Vector Similarity (벡터 유사도)

#### 패러다임 변화

**기존 방식**:
```
Keyword 매칭
- 정확히 일치하는 단어 찾기
```

**새로운 방식**:
```
Embedding을 통한 유사도 계산
- 의미적 유사성 파악
```

---

#### Transformer & 벡터 유사도

**방법**:
- **Transformer 모델 사용**
- **같은 공간에서 벡터 유사도 판단!**

---

#### 질의의 넓은 스펙트럼

**짧은 쿼리**:
```
특징:
- 질의 의도의 모호함
- 컨텍스트 정보가 더 필요

필요:
- 개인화/추천이 더 필요함
```

**긴 쿼리**:
```
특징:
- 질의 의도가 명확
- 컨텍스트 정보가 충분

장점:
- 인공신경망 모델이 잘함
```

---

### 4.2 ANN과 Vector DB

#### ANN (Approximate Nearest Neighbor)

**문제**:
```
벡터 유사도 계산 비용 이슈
- 문서의 양이 많아지면 계산량 폭증
```

**해결책**:
```
ANN 기술 적용이 필수
```

**개념**:
- **벡터 유사도 계산을 전체가 아닌 일부만 함**
- **비슷한 공간에 위치한 것끼리만 계산**

**Trade-off**:
```
✅ 장점: 계산 비용이 확 줄어듦
⚠️ 단점: 정확도는 떨어짐
```

---

#### 주요 ANN 알고리즘

**1. LSH (Locality Sensitive Hashing)**
```
방법: 해시 함수를 사용하여 유사한 벡터를 같은 버킷에 매핑
```

**2. HNSW (Hierarchical Navigable Small World Graphs)**
```
방법: 계층적 그래프 구조를 사용하여 효율적인 검색
```

---

#### Vector DB

**등장 배경**:
- ANN을 지원하는 다양한 Vector DB 솔루션들이 생겨남

**대표 솔루션**:
- Pinecone
- Weaviate
- Milvus
- Qdrant
- ChromaDB

---

## 5. 패러다임의 변화

### 5.1 새로운 기술의 등장 - LLM

#### GPT-3.5 & ChatGPT의 등장

**시점**:
- **2022년 11월 OpenAI의 GPT-3.5 및 ChatGPT 등장**

**영향**:
- **IR 분야도 지각 변동**

---

#### 고차원 언어 이해

**가능해진 것**:
- **고차원 언어 이해가 가능해짐**

**검색의 일부 영역을 LLM이 대체**:
1. **일반 상식 등 지식형 질의**
2. **요약이나 정리가 필요한 질문**

---

#### 여전히 남은 이슈

**1. 환각 (Hallucination) 이슈**
```
문제:
- 실재하지 않는 정보를 그럴듯하게 만들어냄

예시:
- 맛집 추천 (존재하지 않는 식당)
- 인명 검색 (잘못된 정보)

대응:
- LLM 사용 시 fact check 필요성이 커짐
```

**2. Knowledge Cutoff (지식 단절)**
```
문제:
- 모델이 학습된 특정 시점까지의 정보만 다룰 수 있음

예시:
- 2023년 1월까지 학습된 모델은 그 이후 정보를 모름
```

---

### 5.2 검색에서 대화로 - RAG

#### RAG (Retrieval-Augmented Generation)

**정의**:
- **LLM과 IR의 결합으로 대화형 검색 가능해짐**

**역할 분담**:
```
IR: 적합한 정보를 추출
LLM: 지식보다 추론 능력을 활용
```

---

#### RAG의 주요 기능

**1. Standalone Query 생성**
```
- 대화 히스토리로부터 standalone query를 생성하도록 지시
- 문맥을 고려한 독립적인 질의 생성
```

**2. 문서 적합성 판단**
```
- 검색엔진에서 추출된 문서들이 질의에 얼마나 적합한지 판단
```

**3. 답변 생성**
```
- 질의에 적합한 레퍼런스 정보와 대화 히스토리를 주고
- 적합한 답변을 생성하게 지시
```

---

#### RAG의 장점

**1. 자연스러운 인터페이스**
```
원하는 정보를 인간이 가장 익숙한 대화 형태의 인터페이스로 제공
```

**2. 사실 기반 정보 제공**
```
검색 결과를 레퍼런스로 활용하여 사실에 기반한 정보 제공
```

**3. 지능적인 요약/정리**
```
검색 결과의 나열을 넘어 질문 의도에 맞게 요약/정리
```

---

### 5.3 변하지 않는 것

#### 전처리의 중요성

**핵심 원칙**:
```
지속적으로 갱신되는 휘발성 정보는 
학습보다는 처리의 대상
→ 전처리의 중요성!
```

---

#### 정보의 특성에 맞는 기술 활용

**현실**:
```
언어모델이 세상의 모든 지식을 다룰 수는 없음
```

---

#### LLM과 IR의 역할 구분

**IR (Information Retrieval)**:
```
역할: 정보에 대한 색인과 검색 기능을 제공

대상:
- 단순 지식
- 휘발성 정보

기능:
- 지속적으로 갱신되는 정보의 처리
- 원하는 조건으로 빠르게 정보 추출
```

**LLM (Large Language Model)**:
```
역할: 언어의 공통 패턴과 추론 능력을 학습

대상:
- 어휘
- 언어의 공통 패턴
- 추론 능력

기능:
- 의도 분석 / 적합한 질의 생성
- 질의와 레퍼런스로 정리된 대답 생성
```

## 전체 요약

### 검색엔진 발전 과정
```
1세대: Keyword Matching + 역색인
  ↓
2세대: 랭킹 알고리즘 (TF-IDF, BM25, PageRank)
  ↓
3세대: 인공신경망 + 벡터 유사도
  ↓
4세대: LLM + RAG (대화형 검색)
```

---

### 핵심 기술 비교

| 기술 | 특징 | 장점 | 단점 |
|------|------|------|------|
| **역색인** | 단어→문서 매핑 | 빠른 검색 | 키워드 매칭만 가능 |
| **랭킹** | 적합도 계산 | 우선순위화 | 지속적 최적화 필요 |
| **벡터 유사도** | 의미 기반 검색 | 의미적 유사성 파악 | 계산 비용 높음 |
| **ANN** | 근사 최근접 이웃 | 계산 비용 감소 | 정확도 하락 |
| **RAG** | LLM + IR | 대화형 인터페이스 | 환각, 지식 단절 이슈 |

---

### IR의 핵심 이슈와 해결책

| 이슈 | 해결책 |
|------|--------|
| **속도** | 역색인, ANN, Vector DB |
| **품질** | 랭킹 알고리즘, 피드백 |
| **유지보수** | 인공신경망, 자동화 |
| **자연어 이해** | LLM, Transformer |
| **대화형 인터페이스** | RAG |
| **환각 문제** | IR과 결합 (사실 기반) |

---

### 랭킹 요소 정리

**1. 질의-문서 유사도**:
```
- TF-IDF: 단어 빈도와 역문서 빈도
- BM25: TF-IDF 개선 버전
```

**2. 문서 품질**:
```
- PageRank: 링크 구조 분석
- Spam Score: 스팸 문서 판별
- Recency: 최신성 반영
```

**3. 사용자 피드백**:
```
- 클릭률 (CTR)
- 체류 시간 (Dwell Time)
- 이탈률 (Bounce Rate)
```

---

### ANN 알고리즘 비교

| 알고리즘 | 방법 | 특징 |
|----------|------|------|
| **LSH** | 해시 기반 | 구현 간단, 속도 빠름 |
| **HNSW** | 그래프 기반 | 높은 정확도, 메모리 효율 |

---

### RAG 작동 과정
```
1. 사용자 질의 입력
   ↓
2. 대화 히스토리 분석
   ↓
3. Standalone Query 생성 (LLM)
   ↓
4. 문서 검색 (IR)
   ↓
5. 문서 적합성 판단 (LLM)
   ↓
6. 답변 생성 (LLM + Retrieved Docs)
   ↓
7. 사용자에게 답변 제공
```

---

### LLM vs IR 역할 구분
```
지식 저장 관점:

LLM:
- 언어 패턴, 추론 능력
- 일반 상식, 언어 이해

IR:
- 휘발성 정보, 최신 정보
- 특정 도메인 지식


기능 관점:

LLM:
- 의도 분석
- 질의 생성
- 답변 생성

IR:
- 정보 색인
- 빠른 검색
- 조건 필터링
```

## 실전 활용 가이드

### 검색 시스템 설계

**기본 구성**:
```
1. 역색인 구축
2. 랭킹 알고리즘 적용
3. Vector DB 구축 (선택)
4. RAG 파이프라인 구축 (선택)
```

---

### 상황별 기술 선택

**키워드 검색이 중요한 경우**:
```
→ 역색인 + BM25
```

**의미 기반 검색이 중요한 경우**:
```
→ Embeddings + Vector DB + ANN
```

**대화형 인터페이스가 필요한 경우**:
```
→ RAG (LLM + IR)
```

**실시간 정보가 중요한 경우**:
```
→ IR 우선, LLM은 보조
```

---

### RAG 구현 체크리스트
```
✅ 문서 전처리 및 청크 분할
✅ Embeddings 생성
✅ Vector DB에 저장
✅ 검색 알고리즘 선택 (BM25 or Semantic Search)
✅ LLM 프롬프트 설계
✅ 대화 히스토리 관리
✅ 답변 생성 및 검증
✅ 사실 확인 (Fact Checking)
```

## 주요 개념 정리

### TF-IDF (Term Frequency - Inverse Document Frequency)
```
정의: 단어 빈도와 역문서 빈도를 이용한 가중치 계산
목적: 문서 내 중요한 단어 식별
공식: TF × IDF
```

### BM25 (Best Matching 25)
```
정의: TF-IDF를 개선한 확률론적 검색 모델
특징: 문서 길이 정규화, 포화 함수 적용
용도: 전통적인 검색 엔진에서 널리 사용
```

### PageRank
```
정의: 링크 구조를 분석하여 웹 페이지의 중요도 계산
개발: 구글의 핵심 알고리즘
원리: 중요한 페이지로부터 링크를 받으면 중요도 상승
```

### Embedding
```
정의: 텍스트를 고차원 벡터로 변환
목적: 의미적 유사성을 수치로 표현
방법: Transformer, BERT, Sentence-BERT 등
```

### ANN (Approximate Nearest Neighbor)
```
정의: 정확한 최근접 이웃 대신 근사값 찾기
목적: 검색 속도 향상
Trade-off: 속도 ↑, 정확도 ↓
```

## 트렌드 및 미래 방향

### 현재 트렌드
```
1. RAG가 대세
2. Vector DB 생태계 확장
3. Hybrid Search (키워드 + 의미)
4. 멀티모달 검색 (텍스트 + 이미지)
```

### 미래 방향
```
1. 완전 자동화된 대화형 검색
2. 개인화된 검색 경험
3. 실시간 팩트 체크
4. 멀티모달 통합 검색
```
