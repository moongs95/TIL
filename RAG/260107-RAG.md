# RAG

- Retrieval-Augmented Generator
- fine-tuning only
- BERT encoder, BART generator

## Retrieve-then-predict

- retriever-generator 구조
- reader와 다르게 추출하는 것이 아닌 직접 생성
- main goal과 retrieve는 동일하지만 generate 부분이 다름
- generate : z와 x와 이전 시점 토큰들이 주어졌을 때 출력값 y예측

## RAG-Retriever

- DPR : Dense Passage Retrieval 사용

## RAG-Generator

- BART 모델 사용
- denoising 방식으로 학습된 seq2seq 모델
- Token Masking, Sentence Permutation, Document Rotation, Token Deletion, Text Infilling

## RAG-Sequence Model

- 각 문서를 고정 시켜 놓고 각각의 시퀀스를 생성
- 확률 분포 고려

## RAG-Token Model

- 개별적 토큰 생성 : 모든 문서 고려
- 다음 토큰 생성 : 모든 문서, 이전 토큰 고려

## Joint training

- Training loss : input-output pair를 고려함

## Decoding: RAG-Token Model

### Greedy

- 각 시점 확률이 가장 높은 token을 선택
- 단점: 한 번이라도 잘못되면 겉잡을 수 없이 틀림, 항상 높은 확률이 정답은 아님

### Exhaustive

- 가능한 모든 값 검증
- 끝까지 진행한 후(EOS) 가장 높은 확률 sequence 선택
- 단점: computing cost가 많이 듦

### Beam Search

- Greedy와 Exhaustive의 절충안
- greedy는 가장 높은 확률 한 개만 선택하지만
- beam search는 N개를 선택

## Decoding: RAG-Sequence Model

- top k 고르기
- 각 document z1, z2에서 후보 시퀀스 -> hypothesis
- 각각의 hypothesis의 확률을 구함
- 조건부 확률을 구하는 계산식에서 사용되지 않은 문서와 후보가 고려되어야 할 경우
- solution 1. Thorough Decoding : 추가로 넣을 수 있음 -> computing cost
- solution 2. Fast Decoding : 등장하지 않는 경우 확률은 0으로 취급함

## Evaluation

- Open-Domain QA Test Scores
- Human assessments

### Index hot-swapping

- 같은 년도의 index를 쓸 경우 acc는 높지만
- 다른 년도의 index를 쓸 경우 acc는 확 내려감
- retrieval을 잘 하고 있다는 뜻

|---|---|---|---|
| retrieval inference | Pre-train + Fine-tuning | Fine-tuning | Fine-tuning |
| retrieval object | token | document | document |
| type | generative | extractive | generative |
