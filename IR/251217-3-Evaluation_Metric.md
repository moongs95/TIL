# Evaluation Metric (평가 지표)

## 1. Precision & Recall

### 1.1 Precision & Recall 개념

#### 기본 지표

**Confusion Matrix 용어**:
```
TP (True Positive): 관련 있는 문서를 관련 있다고 올바르게 추출
FP (False Positive): 관련 없는 문서를 관련 있다고 잘못 추출
FN (False Negative): 관련 있는 문서를 관련 없다고 잘못 판단
TN (True Negative): 관련 없는 문서를 관련 없다고 올바르게 판단
```

---

#### Precision (정밀도)

**정의**:
- **추출된 문서 중 실제로 관련 있는 문서의 비율**

**공식**:
```
Precision = TP / Retrieved Documents
         = TP / (TP + FP)
```

**의미**:
- "모델이 관련 있다고 판단한 문서들 중 실제로 관련 있는 문서의 비율"
- **정확성**을 측정

---

#### Recall (재현율)

**정의**:
- **실제 관련 있는 문서 중 추출된 문서의 비율**

**공식**:
```
Recall = TP / Relevant Documents
       = TP / (TP + FN)
```

**의미**:
- "실제 관련 있는 문서들 중 모델이 찾아낸 문서의 비율"
- **완전성**을 측정

---

#### Accuracy (정확도)

**정의**:
- **전체 문서 중 올바르게 판단한 문서의 비율**

**공식**:
```
Accuracy = (TP + TN) / Total Documents
         = (TP + TN) / (TP + TN + FP + FN)
```

**참고**:
- IR에서는 TN이 매우 크기 때문에 Accuracy는 좋은 지표가 아님

---

#### Precision-Recall Curve

**특징**:
- **Precision과 Recall 하나만으로 지표를 삼을 수 없음**
- 두 지표는 Trade-off 관계

**관계**:
```
Recall을 높이면 → Precision 낮아짐
Precision을 높이면 → Recall 낮아짐
```

---

### 1.2 추가적인 고려사항

#### 현실적인 이슈

**1. 대규모 문서에서 Recall의 한계**

**문제**:
```
대규모 문서를 다루는 IR에서는 Recall은 큰 의미가 없음
```

**이유**:
```
- IR 모델의 문서 추출 결과에 대하여 최대 k개까지가 관심사인 경우가 많음
- 특히, UX 관점에서의 이슈
- 사용자는 보통 상위 10~20개만 확인
```

**해결책**:
```
Precision@k: 추출된 결과 중 k개까지만의 precision
```

---

**2. 단일 지표의 한계**

**문제**:
```
Precision과 Recall 하나만으로는 모델의 성능을 제대로 표현하기 힘듦
```

**해결책 1: F1-Score**
```
공식: F1-score = 2 × (Precision × Recall) / (Precision + Recall)

특징: Precision과 Recall의 조화평균
```

**해결책 2: Average Precision (AP)**
```
정의: Precision-Recall curve의 아래쪽 면적
```

---

**3. 추가 고려사항**

**순서 및 Relevance 정도**:
```
추출된 결과의 순서 및 Relevance가 이분법으로 떨어지지 않는 경우에 대한 고려
```

**충분한 샘플**:
```
실제 평가는 하나의 질의 결과만을 가지고 하지 않고 충분히 많은 샘플을 사용함
→ 신뢰도 확보를 위해 N개 결과의 평균을 취함
```

---

## 2. 주요 IR Evaluation Metric

### 2.1 MRR (Mean Reciprocal Rank)

#### 개념

**정의**:
- **관련 있는 문서가 몇 번째에 있는지에 중점**을 두고 평가
- **가장 상위 관련 문서의 위치만**을 고려하여 계산

**공식**:
```
MRR = (1/N) × Σ(1/rank_i)

where:
- N: 질의의 개수
- rank_i: i번째 질의에서 첫 번째 관련 문서의 순위
```

**예시**:
```
질의 1: 첫 관련 문서가 1위 → 1/1 = 1.0
질의 2: 첫 관련 문서가 3위 → 1/3 = 0.333
질의 3: 첫 관련 문서가 2위 → 1/2 = 0.5

MRR = (1.0 + 0.333 + 0.5) / 3 = 0.611
```

---

#### MRR 사용 시 고려사항

**적합한 경우**:

**1. 정답이 하나 또는 소수인 경우**
```
✅ 적합: 질의에 대한 명확한 정답이 하나
❌ 부적합: 적합한 정답이 여러 개가 될 수 있는 경우 → 다른 metric 사용
```

**2. 정답이 잘 알려져 있거나 명확한 경우**
```
✅ 적합성 유무가 이분법적으로 명확히 구분되는 경우
   (얼마나 적합한가에 대한 정도는 고려할 필요 없는 경우)

✅ 새로운 문서보다는 이미 사용자가 알고 있는 문서 중
   가장 선호할 만한 문서를 보여주고자 할 때 용이
```

**활용 예시**:
- Q&A 시스템
- 검색어 자동완성
- 특정 페이지 찾기

---

### 2.2 MAP (Mean Average Precision)

#### 개념

**정의**:
- **질의 N개에 대한 Average Precision의 평균값**

**Average Precision (AP) 공식**:
```
AveP = Σ[P(k) × rel(k)] / total number of relevant documents

where:
- P(k): k번째까지의 Precision
- rel(k): k번째 문서가 관련 있으면 1, 아니면 0
```

**MAP 공식**:
```
MAP = (1/N) × Σ(AveP_i)

where:
- N: 질의의 개수
- AveP_i: i번째 질의의 Average Precision
```

---

#### 계산 예시

**질의 1의 결과**:
```
순위 1: 관련O → P(1) = 1/1 = 1.0
순위 2: 관련X → (계산 안 함)
순위 3: 관련O → P(3) = 2/3 = 0.667
순위 4: 관련O → P(4) = 3/4 = 0.75

관련 문서 총 3개
AP = (1.0 + 0.667 + 0.75) / 3 = 0.806
```

---

#### MAP 사용 시 고려사항

**적합한 경우**:

**1. 적합한 문서가 다수일 때**
```
✅ 상위 N개의 관련된 문서에 대해 전부 점수를 반영할 수 있음
✅ 관련된 문서의 위치에 따라 점수에 차등을 줄 수 있는 평가 모델
```

**2. 위치에 따른 가중치**
```
✅ 상위에 있는 오류에 대해서는 가중치를 더 줌
✅ 하위에 있는 오류에 대해서는 가중치를 적게 줌
✅ 평가의 정밀도를 높일 수 있음
```

**3. 정답이 명확한 경우**
```
✅ 적합성 유무가 이분법적으로 명확히 구분되는 경우
   (얼마나 적합한가에 대한 정도는 고려할 필요 없는 경우)
```

**활용 예시**:
- 문서 검색
- 정보 검색 시스템
- 이미지 검색

---

### 2.3 NDCG (Normalized Discounted Cumulative Gain)

#### 개념

**정의**:
- 문서의 관련 여부에 대해 이분법적으로 구분하지 않음
- **더 관련 있는 문서가 어떤 것인지에 중점**
- **덜 관련 있는 문서보다 상대적으로 더 관련 있는 문서를 상위에 노출시키는지를 평가**

**특징**:
- **순위별로 가중치 값을 다르게 적용**하여 계산
- **최종적으로 점수가 1에 가까울수록 좋은 결과**

---

#### CG (Cumulative Gain)

**정의**:
- **순위에 있는 문서들의 연관도 합**

**공식**:
```
CG@k = Σ(rel_i)

where:
- rel_i: i번째 문서의 관련도 점수
- k: 상위 k개 문서까지
```

**예시**:
```
순위 1: 관련도 3
순위 2: 관련도 2
순위 3: 관련도 3
순위 4: 관련도 0
순위 5: 관련도 1

CG@5 = 3 + 2 + 3 + 0 + 1 = 9
```

---

#### DCG (Discounted Cumulative Gain)

**정의**:
- **순위에 따라 가중치를 부여**
- 관련 있는 문서들이 낮은 순위에 있을수록 점수가 낮아짐

**공식**:
```
DCG@k = Σ(rel_i / log₂(i + 1))

또는

DCG@k = Σ((2^rel_i - 1) / log₂(i + 1))
```

**의미**:
- 상위에 있을수록 가중치가 높음 (log로 할인)
- 하위로 갈수록 가중치가 낮아짐

**예시**:
```
순위 1: 3 / log₂(2) = 3 / 1 = 3.0
순위 2: 2 / log₂(3) = 2 / 1.585 = 1.262
순위 3: 3 / log₂(4) = 3 / 2 = 1.5
순위 4: 0 / log₂(5) = 0
순위 5: 1 / log₂(6) = 1 / 2.585 = 0.387

DCG@5 = 3.0 + 1.262 + 1.5 + 0 + 0.387 = 6.149
```

---

#### NDCG (Normalized DCG)

**정의**:
- **DCG에 정규화를 적용**
- 관련 있는 문서의 수가 많아질수록 DCG 값이 증가하는 것을 보완
- **IDCG (Ideal DCG)에 대한 비율**

**공식**:
```
NDCG@k = DCG@k / IDCG@k

where:
- IDCG: Ideal DCG (최선의 문서 순위 결과일 경우 DCG 값)
```

**IDCG 계산**:
```
관련도를 내림차순으로 정렬한 후 DCG 계산
```

**의미**:
- **최종적으로 NDCG는 가장 이상적인 문서 순위 대비 현재 모델의 순위 결과가 얼마나 좋은지를 평가**
- 0 ~ 1 사이의 값
- 1에 가까울수록 이상적

---

#### NDCG 계산 예시

**실제 결과**:
```
순위 1: 관련도 3
순위 2: 관련도 2
순위 3: 관련도 3
순위 4: 관련도 0
순위 5: 관련도 1

DCG@5 = 6.149 (위에서 계산)
```

**이상적인 결과 (관련도 내림차순)**:
```
순위 1: 관련도 3 → 3 / log₂(2) = 3.0
순위 2: 관련도 3 → 3 / log₂(3) = 1.893
순위 3: 관련도 2 → 2 / log₂(4) = 1.0
순위 4: 관련도 1 → 1 / log₂(5) = 0.431
순위 5: 관련도 0 → 0

IDCG@5 = 3.0 + 1.893 + 1.0 + 0.431 + 0 = 6.324
```

**NDCG 계산**:
```
NDCG@5 = DCG@5 / IDCG@5
       = 6.149 / 6.324
       = 0.972
```

---

#### NDCG 사용 시 고려사항

**적합한 경우**:

**1. 관련성과 순위 모두 중요**
```
✅ NDCG는 검색된 문서의 관련성과 그 순위를 모두 고려하여 평가
✅ 사용자가 최상위에 위치한 검색 결과에 더 많은 가치를 두는 경우에 적합
```

**2. 다양성이 필요한 경우**
```
✅ 검색 결과의 다양성이 필요한 경우 유리
```

**3. 관련도가 다양한 값**
```
✅ 문서의 적합도가 이분법이 아니라 다양한 값으로 정량화 가능한 경우 효과적
예시: 매우 관련 있음(3), 관련 있음(2), 약간 관련 있음(1), 관련 없음(0)
```

---

**단점**:

**정답셋 구축 비용**
```
❌ 정답셋 구축 비용이 상대적으로 큼
❌ 적합도에 대한 명확한 기준을 잡기 힘든 경우가 많음
❌ 객관적인 정답셋을 구축하기 힘듦
```

**활용 예시**:
- 검색 엔진
- 추천 시스템
- 랭킹 시스템

---

## 전체 요약

### 평가 지표 비교

| 지표 | 측정 대상 | 관련도 | 순위 고려 | 적합한 경우 |
|------|----------|--------|----------|------------|
| **Precision** | 정확성 | 이분법 | ❌ | 추출 정확도 중요 |
| **Recall** | 완전성 | 이분법 | ❌ | 놓치지 않는 것 중요 |
| **F1-Score** | 균형 | 이분법 | ❌ | 정확성+완전성 균형 |
| **MRR** | 첫 정답 위치 | 이분법 | ✅ | 정답 하나, 위치 중요 |
| **MAP** | 평균 정밀도 | 이분법 | ✅ | 정답 여러 개, 위치 중요 |
| **NDCG** | 정규화 이득 | 다단계 | ✅ | 관련도 다양, 순위 매우 중요 |

---

### 관련도 표현 방식

**이분법 (Binary)**:
```
관련 있음(1) vs 관련 없음(0)

사용 지표: Precision, Recall, F1, MRR, MAP
```

**다단계 (Multi-level)**:
```
매우 관련 있음(3) > 관련 있음(2) > 약간 관련 있음(1) > 관련 없음(0)

사용 지표: NDCG
```

---

### Precision vs Recall Trade-off
```
높은 Precision:
- 추출된 것은 대부분 정답
- 하지만 놓친 정답이 많을 수 있음

높은 Recall:
- 정답을 거의 다 찾음
- 하지만 오답도 많이 포함될 수 있음

균형:
- F1-Score 사용
```

---

### 순위 가중치

**MRR**:
```
첫 번째 관련 문서만 고려
1위: 1/1
2위: 1/2
3위: 1/3
...
```

**MAP**:
```
모든 관련 문서 고려
상위에 있을수록 높은 가중치
```

**NDCG**:
```
모든 문서 고려 + 관련도 정도
log₂(i+1)로 할인
```

---

### 지표 선택 가이드
```
질문: 정답이 몇 개인가?

하나:
→ MRR

여러 개:
→ 질문: 관련도를 몇 단계로 나눌 수 있는가?
   
   2단계 (있다/없다):
   → MAP
   
   3단계 이상:
   → NDCG
```

---

### 실전 활용

**검색 엔진**:
```
주 지표: NDCG@10, MAP@10
보조 지표: MRR, Precision@10
```

**Q&A 시스템**:
```
주 지표: MRR, Precision@1
보조 지표: Recall@5
```

**추천 시스템**:
```
주 지표: NDCG@20, MAP@20
보조 지표: Precision@10, Recall@20
```

**문서 검색**:
```
주 지표: MAP@50, NDCG@50
보조 지표: Precision@10, MRR
```

## 상세 계산 예시

### 예시 데이터

**질의**: "머신러닝"

**검색 결과 (상위 5개)**:
```
순위 1: "머신러닝 입문" - 매우 관련 (3)
순위 2: "딥러닝 기초" - 관련 (2)
순위 3: "AI 개론" - 무관 (0)
순위 4: "머신러닝 알고리즘" - 매우 관련 (3)
순위 5: "통계학 기초" - 약간 관련 (1)
```

---

### Precision & Recall 계산

**이분법으로 변환** (관련도 1 이상 = 관련):
```
순위 1: 관련 O
순위 2: 관련 O
순위 3: 관련 X
순위 4: 관련 O
순위 5: 관련 O

TP = 4 (1, 2, 4, 5)
FP = 1 (3)
```

**가정**: 실제 관련 문서가 총 10개
```
Precision = 4 / 5 = 0.8
Recall = 4 / 10 = 0.4
F1 = 2 × (0.8 × 0.4) / (0.8 + 0.4) = 0.533
```

---

### MRR 계산
```
첫 번째 관련 문서: 순위 1

RR = 1 / 1 = 1.0

여러 질의가 있다면:
MRR = (1.0 + 다른 질의들의 RR) / 질의 개수
```

---

### MAP 계산

**각 관련 문서 위치에서 Precision 계산**:
```
순위 1 (관련): P(1) = 1/1 = 1.0
순위 2 (관련): P(2) = 2/2 = 1.0
순위 3 (무관): 계산 안 함
순위 4 (관련): P(4) = 3/4 = 0.75
순위 5 (관련): P(5) = 4/5 = 0.8

관련 문서 4개
AP = (1.0 + 1.0 + 0.75 + 0.8) / 4 = 0.888
```

---

### NDCG 계산

**DCG 계산**:
```
순위 1 (3): 3 / log₂(2) = 3.0
순위 2 (2): 2 / log₂(3) = 1.262
순위 3 (0): 0 / log₂(4) = 0
순위 4 (3): 3 / log₂(5) = 1.292
순위 5 (1): 1 / log₂(6) = 0.387

DCG@5 = 5.941
```

**IDCG 계산** (이상적 순서: 3, 3, 2, 1, 0):
```
순위 1 (3): 3 / log₂(2) = 3.0
순위 2 (3): 3 / log₂(3) = 1.893
순위 3 (2): 2 / log₂(4) = 1.0
순위 4 (1): 1 / log₂(5) = 0.431
순위 5 (0): 0 / log₂(6) = 0

IDCG@5 = 6.324
```

**NDCG 계산**:
```
NDCG@5 = 5.941 / 6.324 = 0.939
```

## 핵심 Takeaway
```
📊 Precision: 추출한 것의 정확도

🎯 Recall: 찾아야 할 것을 얼마나 찾았는가

⚖️ F1-Score: Precision과 Recall의 균형

🥇 MRR: 첫 정답의 위치가 중요

📈 MAP: 모든 정답의 위치가 중요 (이분법)

🏆 NDCG: 관련도의 정도 + 순위 (다단계)

💡 IR에서는 Precision@k, MAP@k, NDCG@k가 주로 사용

⚠️ 지표 선택은 문제의 특성에 따라 결정

🔄 실전에서는 여러 지표를 함께 사용
```
