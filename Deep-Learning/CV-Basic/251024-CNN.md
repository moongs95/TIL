# CNN

## 01 CNN 기본 개념 다지기

### 1.1 Convolutional Neural Network

**Overview**

- Convolution Layer: 네트워크가 비전 태스크를 수행하는 데에 유용한 Feature들을 학습할 수 있도록 함
- Activation Function: 네트워크에 비선형성을 가해주는 역할을 함 → 다양한 feature들을 학습할 수 있게
- Pooling Layer: Feature Map에 Spatial Aggregation을 시켜줌 → 정보 취합

### 1.2 Convolution Layer

**Convolution Layer의 역할**

- 네트워크가 비전 태스크를 수행하는 데에 유용한 Feature들을 학습할 수 있도록 함
- Filter(=Kernel): Input Image를 특정 크기의 Filter를 이용하여 탐색하면서 Convolution 연산을 시행하여 Filter 영역에 대한 특징을 추출

- receptive field를 통해 4번의 convolution 연산 → 2x2형태의 feature
- filter에 따라 결과가 달라짐 → filter 학습
- Stride (S): Filter를 얼마만큼의 간격으로 움직이는 지를 나타냄

output size = ((N-F) / S)+1 

- N: input의 크기
- F: filter의 크기
- S: stride의 크기

Q. Convolution Layer를 거치게 되면 Feature Map의 크기는 무조건 줄어들까?
= Convolution Layer를 무한으로 쌓을 수 없을까?

- Padding(P): Feature Map의 크기를 일정 수준으로 유지하기 위해서 임의의 값을 넣은 Pixel을 얼마나 추가했는지를 나타냄
    - Zero Padding: 0으로 채운 Pixel을 주변에 채워 넣는 것

output size = ((N-F+2P) / S)+1 

- N: input의 크기
- F: filter의 크기
- S: stride의 크기
- P: padding의 크기

### 1.3 Activation Function

**Activation Function의 역할**

- 모델이 **비선형성**을 가질 수 있도록 만들어 줌

- 일차 함수(선형 함수)로는 만족하는 함수를 구할 수 없음
- 고차 함수(비선형 함수)로는 만족하는 함수를 구할 수 있음

→ 복잡한 문제를 해결하기 위해서는 비선형성을 지닌 모델이 유리하다!

**Convolution 연산만 있는 경우는 어떨까?**

- Convolution 연산 결과 1차 함수를 얻게 되므로(행렬곱 + 편향 스칼라 덧셈), Convolution Layer만으로는 선형적인 모델만 만들 수 있게 됨
- 따라서 Convolution 연산을 거친 뒤 비선형성을 지닌 함수(=Activation Function)를 통과시켜준다면, 복잡한 문제도 풀 수 있는 고차함수 모델을 만들 수 있게 됨
- 다양한 activation function : sigmoid, tanh, ReLU, Leaky ReLU, Maxout, ELU

### 1.4 Pooling Layer

**Pooling Layer의 역할**

- Feature Map에 Spatial Aggregation을 시켜줌 → 정보 취합, 다운 샘플링 역할

- Max pooling, Average pooling이 있음
- Feature Map이 줄어들었을 때의 장점
    1. 모델의 파라미터 수가 줄어들게 된다
    2. Receptive Field가 달라지게 된다
- convolution layer들은 학습 가능한 weight들을 가지고 있음. 어떤 데이터를 사용했느냐에 따라 다양한 결과 출력하지만 이런 weight들은 연산을 할때 자원을 소비, 매 convolution 위치마다 필터의 weight와 이미지, 픽셀간의 곱셈, 덧셈을 계속해야함. pooling layer 사용하면 convolution layer의 weight 파라미터를 사용하지 않고도 동일한 크기의 출력 결과(자원 효율성)

### 2.7 Overfitting 방지

**Overfitting**

- 학습 데이터에 너무 과적합(Overfitting)되어 학습되는 경우를 말함
- Overfitting된 모델의 경우 학습 데이터에 대해서는 좋은 성능을 나타내지만, 학습 데이터에서 본 적 없는 테스트 데이터에 대해서는 매우 낮은 성능을 보이게 됨
- 학습 데이터에서 보지 않은 데이터에 대해서 좋은 성능을 보이는 일반화(Generalization)가 잘 된 모델을 만드는 것이 궁극적인 목표이므로 Overfitting을 피하기 위한 방법들이 필요함

→ 궁극적 목표가 일반화! 새로운 데이터에서도 좋은 성능 ⇒ 오버피팅 방지 매우 중요

**AlexNet이 사용한 오버피팅 방지 방법**

**Data Augmentation**

- 학습 데이터에 변형(Augmentation)을 가해서 좀 더 다양성을 지닌 데이터로 학습될 수 있도록 하는 방법 → Flip, Brightness, Contrast, Saturation, Crop

**Dropout**

- 뉴런 중 일부를 일정 비율(p)로 생략하면서 학습을 진행하는 방법
- 몇몇 뉴런의 값을 0으로 바꾸어서 학습 시에 영향을 미치지 못하도록 만들어 일정 뉴런의 값에 치중해 학습되는 것을 방지함
- Dropout은 학습 시에만 행해지고, 테스트를 할 때는 모든 뉴런을 사용함

## 04 ResNet

### 4.1 Revolution of Depth

엄청 깊은 네트워크의 등장 → 사람보다 잘 구분

### 4.2 Residual Connection

일정 수준 이상으로는 더 깊은 레이어를 쌓아도 Training Error와 Test Error 모두 정확도가 오르지 않는 문제

→ 학습 에러 또한 높게 나옴

“Residual Connection”을 도입하여 문제 해결 : convolution 레이어의 입력을 출력에 바로 더해줌 identity

깊은 네트워크일수록 Optimization이 어려움

- Overfitting은 학습 데이터에서는 좋은 성능을 나타내지만, 테스트 데이터에서는 매우 낮은 성능을 보이는 것을 말함
- 그러므로 Training Error와 Test Error 모두 높은 Deep Plain Model의 경우 Overfitting으로 인한 현상이라고 보기 어려움
- 깊은 모델일수록 더 풍부한 Feature에 대해서 학습할 수 있다는 장점이 있음에도 불구하고 성능이 오르지 않은 것은 깊은 모델의 경우 Optimization이 더 어렵기 때문에 발생한 문제라고 해석할 수 있음

⇒ 학습 자체가 제대로 되지 않았음 → 최적화가 어려움

**Identity Mapping**

- 쌓여진 레이어가 그 다음 레이어에 바로 Optimize되는 것이 아니라 Residual Mapping에 Optimize되도록 만듦
- 추가적인 파라미터도 필요하지 않으며, Shortcut Connection만 추가되기 때문에 복잡한 곱셈 연산도 필요하지 않다는 장점을 지니고 있음

모델 F(x)는 F(x) = H(x) 가 되는 방향으로 optimize됨

모델 F(x)에 x를 더해주게 되면 F(x) = H(x) - x 가 되는 방향으로 optimize됨

e.g. F(x) → x로 근사되어야 할 때, Plain Block의 경우 복잡한 연산을 거친 F(x)의 상태가 x가 되도록 해야 함. 반면, Residual Block의 경우에는 F(x) → 0으로 근사하는 쉬운 문제로 바뀌게 되는데, 이는 H(x)-x는 0이 되기 때문! → weight가 0이 되면 됨! 잔차를 학습, 최적화 관점에서 유리

Shortcut Connection : Convolution 연산을 거치지 않은 x값을 뒷 레이어에 더해주어 초반 레이어의 정보가 희석되는 것을 방지

### 4.3 Bottleneck Layer

**깊은 네트워크의 단점**

- Convolution layer를 연속해서 쌓을 때 Feature Map의 Dimension(=Channel)을 커지거나 유지시키면서 다양한 특징에 대한 학습이 가능하도록 함
    - Channel의 수가 늘어난다는 것은, Convolution 연산 시 필요한 Filter의 수가 많아진다는 것을 의미하기 때문
- 하지만 계속해서 Channel의 수가 늘어날 경우 모델이 깊어질수록 연산에 필요한 파라미터 수가 급격하게 늘어나기 때문에 학습에 어려움이 생기게 됨

→ bottleneck layer : 채널의 수를 줄인 상태에서 convolution 연산을 하고 보다 적은 파라미터를 사용하여 다시 채널 수를 늘림

**1x1 Conv의 효과**

- 3x3 Convolution Layer Input과 Output 간의 dimension을 맞추는 데에 사용됨
- Input과 Output간의 채널 수를 맞추면서도 모델의 파라미터 수는 크게 늘리지 않을 수 있게 됨

### 4.4 Batch Normalization

**Batch Normalization의 필요성**

- Input들이 잘 Normalize 되어 있지 않음 (Bias가 클 수 있다)
- 특정 레이어에서 매우 큰 Weight를 가지게 될 수 있음
- 따라서 Input이 각 레이어마다 일정하게 scale 되어 계산될 수 있도록 하는 장치가 필요함
- 각 Dimension을 zero-mean unit-variance로 만들기 위해서는 아래와 같은 식을 거쳐야 함

→ 각 뉴런들에 평균값 빼고 표준편차를 나눔 → 각 뉴런들 zero-mean unit-variance 상태로 만들어 줌

**Batch Normalization 과정**

- Input (x)의 shape = N x D
- Learnable Scale and Shift Parameter (γ, β)의 shape = D
- 즉 γ = σ, β = μ가 되도록 학습함

- normalized된 입력에 학습 가능한 스케일과 쉬프트 파라미터를 도입하여 스케일은 곱해주고 쉬프트만큼 더해 줌 → 각 레이어의 입력들이 일정하게 스케일 및 쉬프트 되어 최적화에 용이해 짐
- 스케일과 쉬프트가 어떻게 학습되냐에 따라 달라짐
- 각 평균과 분산은 배치가 바뀌면서 다른 샘플이 들어오면 달라짐
- 매 배치마다 구해진 평균과 분산의 이동평균을 구하고 이를 테스트에 사용

**Batch Normalization의 역할**

- Deep Network가 잘 학습될 수 있도록 함
- Gradient Flow를 개선시킴
- 더 빠르게 Converge될 수 있도록 함
- 학습 시 Regularization을 한 것 같은 효과를 얻을 수 있음
- 좀 더 Robust한 모델이 될 수 있도록 하는 데에 기여함(강건성) → 학습 데이터에만 있는 특징들이 계속 학습되서 영향을 크게 미치는 것을 미연에 방지
- ResNet에서는 모든 Convolution Layer 이후에 Batch Normalization을 해줌 (Conv - BN - ReLU 의 구조)

## 05 EfficientNet

최적의 Hyperparameter를 탐색 좋은 성능

### 5.1 Baseline Model

**MBConv Block**

- Mobile inverted Bottleneck Convolution (MBConv)
- Depthwise Separable Convolution: Depthwise conv + Pointwise conv
    - Depthwise Conv(공간적 정보) : Channel별로 나누어서 conv 연산 수행 → 기존 conv 연산보다 적은 수의 파라미터로 feature를 추출할 수 있음 k x k x c(원래) → k x k x 1크기, 원래 1채널인걸 c개 받는 것 처럼 ⇒ 각각 독립적이기 때문에 공간적 정보만 가지고 연산을 하고 있다고 봄
    - Pointwise Conv(채널별 정보) : 1x1 conv로 Channel들을 합침 → 채널의 수를 조절하여 전체 파라미터 수가 적어질 수 있도록 함, 입력의 채널들이 출력의 서로 다른 채널들에 영향을 미칠 수 있음, 입력의 채널수와 출력의 채널수가 달라도 1x1이기 때문에 얼마든지 사용 가능 256x3x3x256 → 3x3x256 + 256x256 파라미터 절감

- Squeeze and Excitation: Feature를 압축했다가 증폭하는 과정을 통해 Feature의 중요도를 재조정 함

- CxWxH 를 만드는게 Depthwise Separable Convolution임
- 즉 depthwise separable convolution 결과를 추가로 조정해주는 것
- depthwise는 성능대비 비용측면 선택, 파라미터 수 줄임
- squeeze and excitation을 통해 성능 부분 보완
    - Squeeze : Global Average Pooling 등을 사용하여 1x1xC 크기로 압축하는 과정 → 각 채널의 중요한 정보만 담고 있을 수 있도록 압축한 것
    - Excitation → Recalibration : 1x1xC 형태의 입력을 받아 각 채널의 정보를 활용해 score(0~1)를 추출 → 기존 CxWxH에 곱해줌 → 채널 별 중요도 확인
- 두 개의 FC layer를 더해주어 + sigmoid activation function 통과(0~1값) 각 채널들의 중요도를 추출함 → 이를 기존 Feature Map에 곱해주게 되면, 채널의 중요도가 학습된 새로운 Feature Map을 얻을 수 있음

**Baseline Model Scaling**

- FLOPS vs. Accuracy Trade-off Curve
- 깊은 모델의 필요성 : Resolution이 커지면, 더 큰 Receptive Field가 필요하므로 더 많은 Layer들을 쌓은 깊은 모델이 높은 정확도를 보임
- 더 넓은 Channel의 필요성 : 더 큰 Resolution를 사용하게 되면 이미지의 디테일들, 즉 High Frequency Information에 대한 정보도 포함되어 있다는 장점이 있는데, 이를 효과적으로 사용하기 위해서는 더 큰 Width를 가진 Channel이 필요함

→ 깊이와 해상도 다 높을 수록 정확도 높음

### 5.2 Compound Scaling

모델의 성능을 향상시키는 방법

더 키워도 성능변화가 유의미하지 않은 시점이 옴

→ 세가지 방향 모두 고려해서 모델을 키우자(넓이, 깊이, 해상도)

1. 모델의 Depth를 늘리기
2. Channel Width를 늘리기
3. Input Image의 해상도 높이기
- Individual Scaling: 깊이(d), 넓이(w), 그리고 해상도(r)를 각각 독립적으로 scaling하는 방법
- Compound Scaling: 깊이(d), 넓이(w), 그리고 해상도(r)를 동시에 scaling하는 방법
    - Compound Coefficient(ϕ): uniformly scales network width, depth, and resolution in a principled way
    - 아래 식에서 α, β, γ는 상수이며, small grid search를 통해 결정됨 → 어떤 비율로 각각 분배할 것인지
    - 계산량은 깊이에 비례하고, 나머지 넓이와 해상도의 경우 그 제곱에 비례하므로 아래와 같은 비율로 결정됨

**모델의 Hyperparameter를 업데이트 하는 방법**

- 먼저 ϕ=1로 고정하고, α, β, γ에 대해서 small grid search 수행
    - 그 결과, α=1.2, β=1.1, γ=1.15로 α⋅β²⋅γ²≈2 라는 결과를 얻음
- 다음으로 α, β, γ를 찾은 값으로 고정한 뒤, ϕ를 변화시키며 모델 전체의 크기를 scaling함 → ϕ = 2라면 α=1.2², β=1.1², γ=1.15² baseline model 대비 약 4배 커진 모델

→ compound scaling을 쓴 모델이 모델 크기 대비 성능이 좋음

### 5.3 EfficientNet의 결과

- 비슷한 성능이 지연속도 매우 낮음
- 다른 모델에 비해 모델 크기 대비 성능이 좋음
