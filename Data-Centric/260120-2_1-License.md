# 2-1. 데이터 수집 시 주의 사항 ① 라이선스 (License)

## 01. 라이선스 개요

### 1.1 라이선스의 필요성

**저작권과 라이선스**

- 인간의 지적 활동을 통해 생성된 무형의 재산을 **지식재산(Intangible Property)** 이라고 함
- 지식재산은 **저작권, 특허권, 상표권** 등의 지식재산권으로 보호됨
- 이 중 **저작권(Copyright)** 은 창작자가 창작과 동시에 취득하는 권리

- 저작권법은 저작물의 목적·형태와 관계없이  
  동일한 수준의 **독점적 권리(All Rights Reserved)** 를 부여함

➡️ 이러한 한계를 보완하기 위해  
**라이선스(License, 이용허락)** 를 통해  
타인이 저작물을 사용할 수 있는 조건과 범위를 명시함

- 사용자는 라이선스에 명시된 조건을 반드시 준수해야 함
- 저작자 또한 자신의 의도를 명확히 반영하여 라이선스를 선택해야 함

---

### 1.2 라이선스의 종류

**Data-Centric AI에서 고려해야 할 라이선스**

#### 코드(Code)
- **오픈 소스 라이선스 (Open Source License, OSL)**
- 일반 콘텐츠용 CCL은 부적합  
  (단, 일부 CCL은 사용 가능)
  - CC BY-SA: GPLv3 단방향 호환
  - CC0 Public Domain: 소프트웨어 사용 가능

#### 데이터(Data)
- **크리에이티브 커먼즈 라이선스 (Creative Commons License, CCL)**
- 일반 콘텐츠에 사용되는 CCL을 그대로 적용

---

## 02. 크리에이티브 커먼즈 라이선스 (CCL)

### 2.1 라이선스 개요

**저작권 (Copyright)**  
시, 소설, 음악, 미술, 영화, 연극, 컴퓨터 프로그램 등  
‘저작물’에 대해 창작자가 가지는 모든 권리

**크리에이티브 커먼즈 라이선스 (CCL)**  
비영리기구 **Creative Commons**에서 만든  
저작물 이용 허락 라이선스

#### 침해 사례
- 복제·배포가 허용되지 않은 창작물을  
  무단으로 모델 학습에 사용
- 특정 일러스트레이터의 작품을 학습시켜  
  스타일을 모방하는 이미지 생성 모델 제작  
  (예: OOO Style LoRA)

---

### 2.2 라이선스 종류

#### CCL 이용 허락 조건 (4가지 요소)

1. **저작자 표시 (BY, Attribution)**  
   - 저작자 이름과 출처 표시 필수

2. **비영리 (NC, NonCommercial)**  
   - 연구 등 비영리 목적만 허용
   - 영리 목적 사용 시 별도 계약 필요

3. **변경 금지 (ND, No Derivatives)**  
   - 저작물 수정 및 2차 저작물 생성 금지
   - 원시 데이터로 사용 불가

4. **동일 조건 변경 허락 (SA, Share Alike)**  
   - 2차 저작물 배포 시 동일 라이선스 적용 의무

---

#### CCL 종류

| 종류 | 저작자 표시 | 비영리 | 변경 금지 | 동일 조건 |
|----|-----------|------|----------|---------|
| CC0 | X | X | X | X |
| CC BY | O | X | X | X |
| CC BY-SA | O | X | X | O |
| CC BY-ND | O | X | O | O |
| CC BY-NC | O | O | X | X |
| CC BY-NC-SA | O | O | X | O |
| CC BY-NC-ND | O | O | O | O |

- **CC0**: 저작권 소멸 또는 저작권 포기 (퍼블릭 도메인)

## 03. 오픈 소스 라이선스 (OSL)

### 3.1 라이선스 개요

**소프트웨어 라이선스 (Software License)**  
소프트웨어 사용·복제·배포 권한과 조건을 규정한 계약 또는 법적 문서

**오픈 소스 소프트웨어 (OSS)**  
소스코드가 공개되어 자유롭게  
복제·배포·수정이 가능한 소프트웨어  
- 예: Linux, Apache, Firefox, MySQL

**오픈 소스 라이선스 (OSL)**  
오픈 소스 소프트웨어를  
무료로 사용·수정·복제·배포할 수 있도록 하는 라이선스

---

### 3.2 라이선스 종류

#### 대표적인 오픈 소스 라이선스 비교

| 라이선스 | 사본 제공 | 수정 사실 기재 | 수정 코드 공개 | 동일 라이선스 | 특허 |
|--------|---------|---------------|---------------|--------------|------|
| Apache 2.0 | O | O | X | X | O |
| BSD | X | X | X | X | X |
| EPL | O | X | X | O | O |
| GPLv3 | O | O | O | O | O |
| AGPL | O | O | O | O | O |
| LGPL | O | O | △ | O | O |
| MPL | O | X | O | O | O |
| MIT | O | X | X | X | X |

---

#### BSD형 라이선스

- 소스코드 공개 의무 없음
- 재배포 제약이 매우 적음

- **BSD License**: 매우 자유로운 재배포
- **Apache License**: 특허 관련 규정 명시
- **MIT License**: 짧고 단순, 상업적 사용 자유

---

#### GPL형 라이선스

- **카피레프트(Copyleft)** 조항 포함
- 소스코드 공개 의무 존재

- **GPL**: 사용 시 전체를 GPL로 공개
- **AGPL**: 서버 서비스 제공 시에도 공개 의무
- **LGPL**: 라이브러리 사용 프로그램은 공개 의무 없음

**카피레프트**  
정보는 독점되지 않고 공유되어야 한다는 철학

---

#### MPL형 라이선스

- 기업 주도 오픈소스에서 주로 사용
- 적용 범위를 파일 또는 모듈 단위로 제한

- **MPL**: 파일 단위 라이선스 적용
- **EPL**: 모듈 단위로 기여 범위 판단
